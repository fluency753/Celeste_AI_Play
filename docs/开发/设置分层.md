# 运行设置分层（设计草案，待确认）

协作者的提议：“有些配置适合固定，有些适合临时设置，有些和具体模型相关，拆开来会不会比较合适”。本文按这个思路给出分层方案、每个字段的归属、优先顺序、Codex 的特别处理、续跑与迁移，以及分步实施的顺序。**这是草案，确认前不改代码。**文末列出需要确认的问题。

## 现状：三处耦合

1. **一份“配置”装着四类东西。**控制台的配置（`orchestrator/profiles.py`）把运行页的整张表单平铺存进 `profile.json` 的 `form`，包括：
   - 模型：执行器、提供方、模型、推理强度、压缩窗口；
   - 玩法：模式、开关、可调参数；
   - 每次运行的安排：章节、存档、时限、开始时先暂停；
   - 本机环境：运行方式、端口、录像参数。

   切换配置会把这些一起换掉。比如预置配置 1 写死了 Claude、Opus、high，同一套玩法想换 Codex 跑，只能另存一份。
2. **模型相关的值散在四处：**
   - `configs/providers.json`：推理强度按模型列，但 `autocompact`、`images`、`model_suffix` 是整个提供方共用一个值，Opus（100 万上下文）和 Haiku 共用。
   - 表单：`effort`、`autocompact` 按运行存。换了模型，旧档位可能不受支持。
   - `configs/hud.json`：显示名 `names`、全局 `compact_threshold`（967000，其实是 Opus 的数）、`context_window`（已没有代码读取）。
   - 代码里写死的：Codex 的默认推理强度 `medium`、放行域名与 `images`（`orchestrator/runtimes.py`）；思考汉字上限 Codex 不限（`orchestrator/thought.py`）；游戏内 HUD 的推理强度刻度固定为 low～max 五档（`overlay/modhud.py`）。
3. **执行器差异是隐含的。**
   - 只对 Claude 生效的项，选 Codex 时界面上照样显示：压缩窗口、思考汉字上限、/sim 直接调用、提供方管理。
   - Codex 的模型列表来自容器里固定版本的 Codex。
   - Codex 恢复会话不能更新开会话时登记的工具说明（见下文“会话级设置”）。

## 目标与边界

- 换模型不带走玩法：同一份配置可以用不同模型跑，模型相关的值跟着模型走。
- 预置配置跨模型、跨机器可用：不带本机端口、录像参数等环境设置。
- 每个设置只有一个归属地，来源可见：控制台标出当前值来自本次运行、模型档案、提供方还是默认。
- 执行器差异显式化：不适用的项隐藏或标“不适用”，会话级设置在续跑时有提示。
- **不改：**
  - 命令行仍可覆盖任何一项；
  - 续跑沿用原运行的语义；
  - 密钥存放方式；
  - 主控各模块拿到的仍是一个合并好的 `RunConfig`。分层只发生在控制台与配置存储，以及合并这一步。

## 四层

| 层 | 含义 | 存在哪里 | 切换配置时 |
| --- | --- | --- | --- |
| **本机与组件**（固定） | 这台机器、这套组件的环境，与玩法无关 | 本机设置 `configs/local.console.json`（不入库） | 不变 |
| **模型档案**（与模型相关） | 某个执行器 + 模型的参数 | 入库的 `configs/providers.json` 各模型行，本机覆盖 `configs/local.providers.json` | 不变，跟着所选模型 |
| **玩法配置**（现在的“配置”） | 决定智能体怎么玩、实验是否可比 | 配置目录（`local/profiles/<编号>/`、`configs/presets/<编号>/`） | 换 |
| **本次运行**（临时） | 这一次跑什么、存在哪 | 默认记住上次填写的；配置可以把其中几项“固定”下来 | 不换，除非配置固定了这几项 |

### 模型档案的写法

不另开文件，而是扩展 `providers.json` 现有的 `models[]` 行。行里都是可选项，没写的用提供方或内置的值：

```json
{"id": "opus", "label": "Opus", "display_name": "Opus 5.5",
 "efforts": ["low", "medium", "high", "xhigh", "max"], "default_effort": "high",
 "autocompact": null, "context_limit": null, "images": true,
 "thought": {"max_hanzi": 30, "temp_max_hanzi": 120}}
```

提供方这一级只保留“怎么接入”：`base_url`、`auth`、`allowed_domains`、`allowed_host_ports`、`key_env`、`key_file`、`env`、`model_suffix`、`gateway_check`、`status`。

### 优先顺序

本次运行填写（表单或命令行）> 模型档案 > 提供方 > 开关带来的默认值（例如节省上下文的 50 万窗口）> 内置默认值。

控制台在每个模型相关的字段旁标出当前值的来源。主控把合并后的值、以及每个值的来源一起记进 `run_state.json`。

## Codex 的特别处理

1. **模型列表**仍然取自 Codex 的模型目录。目录随镜像里的 Codex 版本（`CODEX_VERSION`，Dockerfile 与 `orchestrator/codex_container.py` 两处）和项目的 Codex 登录变化。模型档案按模型 ID 叠加；目录里已经没有的 ID 跳过，并在控制台提示。推理强度与默认档位以目录为准，档案只能在其中挑选。
2. **提供方信息改成数据。**在 `providers.json` 加 `codex` 项（`label`、`allowed_domains`、`images`、`default_effort`），`runtimes.py` 只保留执行器的适配逻辑。
3. **会话级设置。**Codex 在开会话时登记工具说明，恢复时不能更新。以下设置会写进工具说明，所以对一个 Codex 会话来说开会话时就定死了：
   - `save_context`；
   - `formal_thought`；
   - `collision_image`；
   - `cutscene_mode`（自动处理那句）；
   - 动作帧数上下限（`max_frames_per_act`、`min_frames_per_act`、`explore_act_frames`）；
   - 解说字数。

   Claude 每次启动都重新读取工具说明，不受这个限制。方案：
   - 控制台在 Codex 续跑时把这些项标为“会话级：改了要新会话才完全生效”；
   - 主控把 1.15.1 里只针对节省上下文的补发做成通用机制：比较当前填好的工具说明与登记的说明，有差异时在恢复后第一轮补发差异。
4. **不适用的项**：选 Codex 时隐藏或标“不适用”的有压缩窗口、思考汉字上限、/sim 直接调用、提供方管理。服务档位（fast）只在 Codex 下显示。
5. **压缩窗口**：Codex 的配置可能支持类似 `model_auto_compact_token_limit` 的压缩阈值，可以经 `thread/start` 的 `config` 传入，从而让“节省上下文”的窗口对两种执行器一致。**要先在固定版本上实测**确认支持，再决定做不做。
6. **HUD**：游戏内 HUD 的推理强度刻度改成按模型档位列表画（网页 HUD 已经这样做了）。GPT 模型的显示名从模型档案或 Codex 目录的 `displayName` 取。

## 续跑

- 续跑沿用原运行记下的玩法、模型与本次运行设置（现在基本如此）。本机层取当前本机值；桥接与 MCP 端口照旧沿用原运行的（控制台的续跑命令现在就这样做）。
- 补记 `autocompact` 的实际值。现在 `run_state.json` 不记它，控制台的续跑命令也不带，所以一次显式设了窗口的运行，从控制台续跑就回到了默认值。
- 记下各值的来源层，复盘时能看出某个值是固定的、跟模型来的，还是这次临时填的。

## 迁移

- 配置的 `profile.json` 版本号加一。读取旧版配置时按上表拆分：
  - 玩法字段留在配置里；
  - 本机字段第一次迁移时写入本机设置，只取当前选中配置里的值，之后各配置不再带；
  - 本次运行字段在已有配置里变成“固定项”，这样不改变已有配置的行为，用户可以取消固定。
- 预置配置 1 迁移后：玩法不变，固定章节与不限时；“推荐模型 Opus、high”作为固定项。
- `hud.json` 的 `names`、`compact_threshold` 迁移进模型档案。迁移期内两处都读，模型档案优先。
- 命令行参数不变：命令行本来就是“本次运行”，覆盖一切。

## 控制台

- 运行页分成四块：本次运行（章节、存档、时限、标签、开始时先暂停）、执行器与模型（含模型档案的值与来源）、玩法（就是配置）、本机（现在“更多设置”里的端口与录像，挪到单独的“本机设置”）。
- “保存配置”只保存玩法和固定项。本机设置改了立即写入本机文件。“未保存的改动”只看玩法与固定项。
- 预览与开跑一致的测试（`calibration/prompt_parity_test.py`）扩展到分层合并：同一组分层输入，预览与开跑得到的设置逐字相同。

## 分步实施

1. **模型档案**：扩展 `providers.json` 模型行；Codex 提供方改成数据；压缩窗口与 HUD 上限、显示名改由模型档案提供；`run_state.json` 记下 `autocompact`。范围小，可以独立发布。
2. **本机层**：端口、录像、HUD 等从配置拆到本机设置，同时迁移。
3. **本次运行与固定项**：记住上次填写；配置可以固定其中几项；迁移已有配置与预置配置 1。
4. **执行器差异显式化**：不适用的项隐藏；Codex 会话级设置的提示与差异补发通用化。
5. 文档（使用说明、部署说明、上手指南）与测试收尾。

## 需要确认的问题

1. `live`、`record`、`play_speed`／`auto_speed` 分别归哪层？
2. 模型选择属于“本次运行”（配置只能固定一个推荐模型），还是属于玩法配置？
3. 用量上限（`max_usage`、`quota_wait`）归本机，还是归提供方账户？
4. Codex 的压缩窗口要不要做？需要先在固定版本上实测。
5. 迁移时，已有配置里的章节、存档等是否都变成固定项（行为不变），还是只保留章节与时限？
