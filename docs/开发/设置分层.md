# 运行设置分层（设计，已确认，分步实施中）

协作者的提议：“有些配置适合固定，有些适合临时设置，有些和具体模型相关，拆开来会不会比较合适”。本文按这个思路给出分层方案、每个字段的归属、优先顺序、Codex 的特别处理、续跑与迁移，以及分步实施的顺序。2026-11-08 已确认，文末记下确认的决定与各步进度。

## 现状：三处耦合

1. **一份“配置”装着四类东西。**控制台的配置（`orchestrator/profiles.py`）把运行页的整张表单平铺存进 `profile.json` 的 `form`，包括：
   - 模型：执行器、提供方、模型、推理强度、压缩窗口；
   - 玩法：模式、开关、可调参数；
   - 每次运行的安排：章节、存档、时限、开始时先暂停；
   - 本机环境：运行方式、端口、录像参数。

   切换配置会把这些一起换掉。比如预置配置 1 写死了 Claude、Opus、high，同一套玩法想换 Codex 跑，只能另存一份。
2. **模型相关的值散在四处：**
   - `configs/providers.json`：推理强度按模型列，但 `autocompact`、`images`、`model_suffix` 是整个提供方共用一个值，Opus（100 万上下文）和 Haiku 共用。
   - 表单：`effort`、`autocompact` 按运行存。换了模型，旧档位可能不受支持。
   - `configs/hud.json`：显示名 `names`、全局 `compact_threshold`（967000，其实是 Opus 的数）、`context_window`（已没有代码读取）。
   - 代码里写死的：Codex 的默认推理强度 `medium`、放行域名与 `images`（`orchestrator/runtimes.py`）；思考汉字上限 Codex 不限（`orchestrator/thought.py`）；游戏内 HUD 的推理强度刻度固定为 low～max 五档（`overlay/modhud.py`）。
3. **执行器差异是隐含的。**
   - 只对 Claude 生效的项，选 Codex 时界面上照样显示：压缩窗口、思考汉字上限、/sim 直接调用、提供方管理。
   - Codex 的模型列表来自容器里固定版本的 Codex。
   - Codex 恢复会话不能更新开会话时登记的工具说明（见下文“会话级设置”）。

## 目标与边界

- 换模型不带走玩法：同一份配置可以用不同模型跑，模型相关的值跟着模型走。
- 预置配置跨模型、跨机器可用：不带本机端口、录像参数等环境设置。
- 每个设置只有一个归属地，来源可见：控制台标出当前值来自本次运行、模型档案、提供方还是默认。
- 执行器差异显式化：不适用的项隐藏或标“不适用”，会话级设置在续跑时有提示。
- **不改：**
  - 命令行仍可覆盖任何一项；
  - 续跑沿用原运行的语义；
  - 密钥存放方式；
  - 主控各模块拿到的仍是一个合并好的 `RunConfig`。分层只发生在控制台与配置存储，以及合并这一步。

## 四层，另加独立的直播与录屏

| 层 | 含义 | 存在哪里 | 切换配置时 |
| --- | --- | --- | --- |
| **本机与组件**（固定） | 这台机器、这套组件的环境，与玩法无关 | 本机设置 `configs/local.console.json`（不入库） | 不变 |
| **模型档案**（与模型相关） | 某个执行器 + 模型的参数 | 入库的 `configs/providers.json` 各模型行，本机覆盖 `configs/local.providers.json` | 不变，跟着所选模型 |
| **玩法配置**（现在的“配置”） | 决定智能体怎么玩、实验是否可比 | 配置目录（`local/profiles/<编号>/`、`configs/presets/<编号>/`） | 换 |
| **本次运行**（临时） | 这一次跑什么、存在哪 | 默认记住上次填写的；配置可以把其中几项“固定”下来 | 不换，除非配置固定了这几项 |
| **直播与录屏**（独立） | 直播模式、OBS 录屏两个开关 | 各自记住上次的选择，不进配置 | 不变 |

提供方账户（用量上限、额度用完后是否等待）归在提供方的设置里，与模型档案放在同一个文件，但属于提供方这一级，不随模型变。

### 字段归属

| 字段（`launch_options.DEFAULTS` 与相关文件） | 层 | 说明 |
| --- | --- | --- |
| `runtime`、`bridge_port`、`mcp_port`、`hud_port`、`hud`、`hud_window`、`hud_mod` | 本机 | `hud_mod` 是显示偏好 |
| `ffmpeg`、`record_video_args`、`audio_offset_ms`、`recording_mode`、`freeze_*`、`keep_obs_open`、`continuous_music` | 本机 | 录像与 OBS 环境 |
| `play_speed`、`auto_speed` | 本次运行（调试） | 控制台的“动作推进速度”：每次渲染推进几帧，大于 1 是快进，只用于调试（录像会失真，录制期间 `play_speed` 不起作用）；不记住 |
| `quota_wait`、`quota_wait_max_hours`、`max_usage` | 提供方账户 | 写在提供方项的 `usage` 里；本次运行（命令行）仍可覆盖。额度等待目前只有 Claude 执行器实现，Codex 下标“不适用” |

| `autocompact` | 模型档案，本次运行可覆盖 | 见下文“优先顺序” |
| 可调参数 `thought_max_hanzi`、`thought_temp_max_hanzi` | 模型档案（按执行器） | 现在 Codex 不限汉字，是写在代码里的执行器差异；总字数上限 `thought_max_chars` 两种执行器都用，留在玩法 |
| `hud.json` 的 `names`、`compact_threshold`、`effort_names` | 模型档案 | 显示名、上下文警示上限、档位名；`hud.json` 只留颜色、章节名等 |
| `mode`、`sim`、`sim_assist`、`stiffness`、`formal_thought`、`save_context`、`collision_image`、`playback` | 玩法 | |
| `live`、`record` | 直播与录屏（独立） | 各自记住上次的选择，切换配置、模型都不变；`live` 会改变提示词与解说节奏，续跑沿用原运行的 |
| `study`、`study_minutes`、`limit_planning`、`rounds_per_room`、`room_scale` | 玩法 | |
| `cutscene_mode`、`action_permissions`、`allow_chapter_reset`、`allow_detour` | 玩法 | |
| 其余可调参数（`tune`） | 玩法 | 帧数上限、程序时长、僵直、限额预测、回放等 |
| `kb_deny`、`kb_allow`、知识库修改、提示词修改、个人追加要求 | 玩法 | 现状不变；个人追加要求已按 `执行器:模式` 分开 |
| `chapters`、`segments`、`sides`、`seg_off`、`map`、`max_minutes` | 本次运行（可由配置固定） | 预置配置 1 会固定章节与不限时 |
| `save`、`agent`、`start_paused` | 本次运行 | |
| `record_marker`、`skip_enter`、`no_agent` | 本次运行（调试） | 不记住，每次回到默认 |

### 模型档案的写法

不另开文件，而是扩展 `providers.json` 现有的 `models[]` 行。行里都是可选项，没写的用提供方或内置的值。`label` 同时是控制台下拉框与 HUD 的显示名，不另设字段：

```json
{"id": "opus", "label": "Opus 5.5",
 "efforts": ["low", "medium", "high", "xhigh", "max"], "default_effort": "high",
 "autocompact": "300000", "context_limit": 967000}
```

- `autocompact`：这个模型的自动压缩窗口（Claude 执行器）。
- `context_limit`：HUD 上下文警示与笔记提醒的上限，与执行器报告的窗口、实际压缩窗口一起取最小的。
- 第四步再加：思考字数上限（`thought`）、按模型的图片支持（`images`）。

提供方这一级只保留“怎么接入”：`base_url`、`auth`、`allowed_domains`、`allowed_host_ports`、`key_env`、`key_file`、`env`、`model_suffix`、`gateway_check`、`status`。

### 优先顺序

本次运行填写（表单或命令行）> 模型档案 > 提供方 > 开关带来的默认值（例如节省上下文的 50 万窗口）> 内置默认值。

控制台在每个模型相关的字段旁标出当前值的来源。主控把合并后的值、以及每个值的来源一起记进 `run_state.json`。

## Codex 的特别处理

1. **模型列表**仍然取自 Codex 的模型目录。目录随镜像里的 Codex 版本（`CODEX_VERSION`，Dockerfile 与 `orchestrator/codex_container.py` 两处）和项目的 Codex 登录变化。模型档案按模型 ID 叠加；目录里已经没有的 ID 跳过，并在控制台提示。推理强度与默认档位以目录为准，档案只能在其中挑选。
2. **提供方信息改成数据。**放进单独的 `configs/codex.json`（本机覆盖 `configs/local.codex.json`），含 `label`、`allowed_domains`、`images`、`default_effort` 与按模型 ID 叠加的 `models`。不放进 `providers.json`，免得出现在 Claude 的提供方列表与“管理提供方”里。`runtimes.py` 只保留执行器的适配逻辑，文件缺失或读不出时用内置的同样数值。
3. **会话级设置。**Codex 在开会话时登记工具说明，恢复时不能更新。以下设置会写进工具说明，所以对一个 Codex 会话来说开会话时就定死了：
   - `save_context`；
   - `formal_thought`；
   - `collision_image`；
   - `cutscene_mode`（自动处理那句）；
   - 动作帧数上下限（`max_frames_per_act`、`min_frames_per_act`、`explore_act_frames`）；
   - 解说字数。

   Claude 每次启动都重新读取工具说明，不受这个限制。方案：
   - 控制台在 Codex 续跑时把这些项标为“会话级：改了要新会话才完全生效”；
   - 主控把 1.15.1 里只针对节省上下文的补发做成通用机制：比较当前填好的工具说明与登记的说明，有差异时在恢复后第一轮补发差异。
4. **不适用的项**：选 Codex 时隐藏或标“不适用”的有压缩窗口、思考汉字上限、/sim 直接调用、提供方管理。服务档位（fast）只在 Codex 下显示。
5. **压缩窗口**：不做。Codex 按它自己的默认压缩；“节省上下文”的 50 万窗口只对 Claude 生效。
6. **HUD**：游戏内 HUD 的推理强度刻度改成按模型档位列表画（网页 HUD 已经这样做了）。GPT 模型的显示名从模型档案或 Codex 目录的 `displayName` 取。

## 续跑

- 续跑沿用原运行记下的玩法、模型与本次运行设置（现在基本如此）。本机层取当前本机值；桥接与 MCP 端口照旧沿用原运行的（控制台的续跑命令现在就这样做）。
- 补记 `autocompact` 的实际值。现在 `run_state.json` 不记它，控制台的续跑命令也不带，所以一次显式设了窗口的运行，从控制台续跑就回到了默认值。
- 记下各值的来源层，复盘时能看出某个值是固定的、跟模型来的，还是这次临时填的。

## 迁移

- 配置的 `profile.json` 版本号加一。读取旧版配置时按上表拆分：
  - 玩法字段留在配置里；
  - 本机字段第一次迁移时写入本机设置，只取当前选中配置里的值，之后各配置不再带；
  - 本次运行字段在已有配置里全部变成“固定项”，这样不改变已有配置的行为。固定项的值和是否固定，用户都可以自己改动并保存。
- 预置配置 1 迁移后：玩法不变，固定章节与不限时；“推荐模型 Opus、high”作为固定项。
- `hud.json` 的 `names`、`compact_threshold` 迁移进模型档案。迁移期内两处都读，模型档案优先。
- 表单里的 `max_usage`、`quota_wait`、`quota_wait_max_hours` 迁到提供方的 `usage`：取当前选中配置里的值写进它所用的提供方，之后表单不再带。
- 命令行参数不变：命令行本来就是“本次运行”，覆盖一切。

## 控制台

- 运行页分成几块：本次运行（章节、存档、时限、标签、开始时先暂停）；执行器与模型（含模型档案的值与来源）；直播与录屏；玩法（就是配置）；本机（现在“更多设置”里的端口与录像，挪到单独的“本机设置”）。用量上限挪进“管理提供方”，Anthropic 订阅也在那里设置。
- “保存配置”只保存玩法和固定项。本机设置改了立即写入本机文件。“未保存的改动”只看玩法与固定项。
- 预览与开跑一致的测试（`calibration/prompt_parity_test.py`）扩展到分层合并：同一组分层输入，预览与开跑得到的设置逐字相同。

## 分步实施

1. **模型档案**（已完成，控制台 1.16.0）：扩展 `providers.json` 模型行（`label` 作显示名、`autocompact`、`context_limit`）；Codex 提供方数据移到 `configs/codex.json`；压缩窗口的默认值与来源、HUD 上限与显示名改由模型档案提供；`run_state.json` 记下显式设的 `autocompact`，续跑与唤起的会话沿用。`hud.json` 的 `names`、`compact_threshold` 仍保留作后备。
2. **本机层与提供方账户**（已完成，控制台 1.17.0）：运行方式、端口、录像与声音、HUD 服务与窗口从配置拆到本机设置（`configs/local.console.json` 的 `machine`，`orchestrator/machine_settings.py`），控制台单独一栏“本机设置”，改了立即保存；第一次读取时按选中配置的表单、本机最近一次运行依次迁移。用量上限迁到提供方的 `usage`，在运行页“智能体与模型”下面按所选提供方设置（不是“管理提供方”对话框：Anthropic 订阅不在那个对话框里），主控在命令行没写时按提供方取值。与原计划的差别：`hud_mod`（游戏内 HUD）的默认值跟着直播开关走，暂时留在玩法；`agent_cpus` 在可调参数里，放到第四步；预置配置文件里的这些键暂时保留，只在第一次迁移时读取，第三步迁移预置配置时去掉。
3. **本次运行与固定项**（已完成，控制台 1.18.0）：本次运行的设置分成七组（执行器与模型、智能体标签、地图与章节、存档、现实时间上限、开始时先暂停、压缩窗口，`machine_settings.RUN_GROUPS`），配置用 `pins` 记下固定了哪些组，只存固定组的值；没固定的组记住上次填写的（`configs/local.console.json` 的 `last`，与原来记住的合并，换到不固定它们的配置时照样用得上）；直播与录屏各自记在 `last`，不进配置；调试项不记住。旧版配置没有 `pins`：存过的组全部算固定，用户可以取消固定再保存。预置配置 1 改成新格式，同时去掉本机设置、用量设置与直播、录屏。
4. **执行器差异显式化**：不适用的项隐藏；思考字数上限进模型档案；游戏内 HUD 的推理强度刻度按模型档位；Codex 会话级设置的提示与差异补发通用化。
5. 文档（使用说明、部署说明、上手指南）与测试收尾。

## 已确认的决定（2026-11-08）

1. 直播与 OBS 录屏单独一组：各自记住上次的选择，不进配置，切换配置、模型都不变。动作推进速度（`play_speed`、`auto_speed`）是调试用的快进，归本次运行（调试），不记住。
2. 模型选择属于本次运行；配置可以把它作为固定项。
3. 用量上限归提供方账户。
4. Codex 的压缩窗口不做。
5. 迁移时已有配置的本次运行字段全部变成固定项；固定项的值和是否固定都可以由用户改动并保存。
