# 按输出 Token 推进游戏

探索模式可选开启 **Token 推进**，默认关闭。控制台的玩法开关启用后，在「可调参数 → 探索：Token 推进」设置 `tokens_per_frame`，默认 **500 token/帧**，接受 1～1,000,000 的整数。命令行在原启动参数后加：

```text
--token-drift --tune tokens_per_frame=500
```

开关和比例随配置、运行状态保存；续跑沿用，可显式用 `--no-token-drift` 关闭或 `--tune` 更改比例。比例不是运行中的热调参数。与按现实时间计费的「思考僵直」互斥，旧配置和预置配置不会自动开启。

新增输出总量包含推理 token，推理量是其子集，不再加一次；输入和缓存读取不计。每次可靠用量通知换算整数帧，不足一帧的 token 余数保留。500 token/帧时，30,000 个输出 token 为 60 帧，即游戏内一秒。收到整批立即推进，不加平滑延迟；每个输入块最多 60 帧，用于及时检查暂停和取消，剩余块可连续执行。

## 用量来源

- Codex：`thread/tokenUsage/updated` 的累计 `total.outputTokens`，用 `last.outputTokens` 限制本次新增量；不把历史总量补收为游戏帧。
- Claude Code：启用 `--include-partial-messages`，按响应 ID 接收 `message_delta.usage.output_tokens` 累计增量，`result.usage` 仅补本轮尚未覆盖的差额。忽略 `message_start` 的占位计数。响应、轮次覆盖量和结果 ID 持久化去重，重连不会重新收费。若上游只在响应结束报告 usage，就在该边界更新；不根据文本长度或等待时间猜 token。
- Claude 的推理 token 子项仅在提供方明确报告时更新；未报告不能据此认为实际没有推理。这里只消费用量元数据，新增的部分文本／推理流不会写入日志。

## 推进边界

只在正在试玩的模型回合接受新增计费，沿用最后真实游戏输入，包括中性输入；执行复用原桥接连接、动作锁、录制检查、停止条件、帧日志、游戏时钟和目标核验。它不占用单次 `act` 帧数限额，也不算一次 Agent 决策。准备、聊天、用户通过 HUD 暂停、网络／额度等待、压缩及维护重载期间不计新费用；这些阶段仍更新用量游标，不在恢复后补收。恢复后首个正增量可能跨越排除期，归属不明时整批保守跳过；之后连续有效的增量才计费，零增量不清除此边界。普通队列的未执行整数帧仍按原规则在暂停／场景变化时丢弃，余数保留；下述菜单待补帧单独保存，不随普通队列丢弃。

**Agent 打开的游戏暂停／日志菜单继续计费。** 菜单期间不发送零帧推进请求，而是累计 `deferred_frames`。取消暂停或重试到首次恢复可操作时，原菜单计划在该边界截断，先保持暂停前最后一帧游戏按键补推进，再返回最新观测；原计划未执行部分须重新规划。菜单里的方向、确认、返回、暂停键不覆盖这份快照；菜单期间须沿用原输入格式，不能通过切换 TAS 格式改变补推进的按键含义。500 token/帧时，菜单期间的30,000 token会在恢复后补60帧。

已有欠帧不会因重试、用户暂停、压缩、主控结束／续跑或换房而清零；每批只核销实际执行的帧数。补推进遇到死亡、换房或剧情立即停并交观测，剩余欠帧保留，不自动重发旧输入或原计划。合法返回地图／保存退出仍按原权限执行，地图 UI 可继续导航；已观察到的同游戏、同存档导航链在重新进入关卡后再结算，地图界面不偿付游戏帧。退出操作本身不证明目标完成，不扩大地图／重开权限。

角色不可操作或有待处理剧情时不推进。死亡、换房、通关、失控或剧情输入使当前块停止，并废弃普通旧队列；必须成功默认 `observe` 后才能继续推进或执行新动作。场景中断之前排队的旧动作即使在观察之后才取得锁，也会被拒绝。此功能不会代按确认、跳过自然死亡动画或选择剧情。

运行结束会等待在途推进归还连接；执行结果不明时暂停，记为 unknown，不重发、不推测已执行帧数。`token_drift.json` 的未确认批次在续跑时继续保持暂停，须人工核验账本；普通「继续」不会清除该保护。进程恢复时普通队列仍不补跑；有已保存菜单上下文的队列转入欠帧，原有欠帧保留。暂停前输入快照校验游戏进程、存档、地图／导航链、帧号、格式与游戏按键，缺失或不符时保留账本并拒绝不明偿付。用量快照先于推进账本提交；两次持久化之间崩溃可能少推进，恢复不补偿这段历史，以免重复输入。

接回1.23.0已经打开的菜单时，可依据同一冻结交接、旧账本进程／地图身份、存档、实际暂停事件及其前一帧日志恢复按键快照；每个历史日志只查末2MiB。缺证据不猜按键，旧版已经丢弃的历史用量不追补。

少数剧情／教程期间角色仍被桥接标为可控，此时仍允许既有剧情输入，按一帧检查恢复边界；结果明确列出未执行输入，停止本次自动重试。PlayerSeeker 的实际可控状态沿用既有识别，不仅依赖 Madeline 的可控标记。暂停／日志按键只执行到首个可能打开菜单的帧，避免长输入吞掉暂停前的按键边界。

## 记录与分析

- `output_usage.json`：Claude 用量权威累计、响应游标及本轮已覆盖量，供重连去重。
- `token_drift.json`：当前比例、源累计游标、余数、普通队列 `pending_frames`、菜单待补 `deferred_frames`、已执行／放弃帧数及最后批次状态。普通队列和菜单债务分别恢复，余数保留。
- `token_menu.json`：GameSession维护的暂停前游戏按键、格式、来源身份／帧和菜单、恢复、可操作或导航阶段；不复制 token 账本。恢复时验证快照和冻结交接；菜单按键不能用于偿付。
- `token_advances.jsonl`：带 Unix 墙钟秒的 usage、deferred、requested、committed、discarded、unknown 事件。批次 `origin=usage/deferred` 区分即时推进与菜单偿付；ID 在运行链内单调增加。requested 表示提交前记录，不证明执行成功，只有 committed 的 consumed 是已确认帧数。
- `metrics.json`：新增 `token_frames`、`token_s`（已确认游戏帧数 / 60）、`token_drift` 摘要；原 `auto_game_s` 仍为自动推进实际墙钟时间，`frames_played` 仍只统计显式动作帧。
- 正式分析导出将批次并入 `tool_calls.jsonl`（`tool=system.token_advance`、`record_kind=system_advance`），稳定工具 ID 关联 `timeline.jsonl` 和结果状态；unknown 的 `success=null`、`status=execution_unknown`，不认定失败、不生成假状态。累计快照附带 `token_frames`／`token_s` 及 `token_drift` 余额摘要；动作结果中的 `token_repayment` 单列补推进，菜单输入与偿付不混算。

模型可在游戏推进时继续生成，因而 `thinking_s` 可能与 Token 推进的 `auto_game_s` 重叠，不能把所有时间列相加当成墙钟总时长。工具期间仍沿用原有扣除游戏执行时间的统计口径。`token_s` 为游戏内秒数，不是执行耗时或模型耗时。

验证使用真实 Claude Code 2.1.309 配合隔离本地 SSE 上游，以及真实执行器／游戏工具入口配合隔离桥接；不连接在用主控。上游实际报告频率和真实 Celeste 长程游玩效果不由协议夹具证明。
