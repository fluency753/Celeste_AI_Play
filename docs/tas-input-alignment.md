# TAS 输入对齐约定

目标是让 agent 能读写、分段执行并分析 CelesteTAS 输入，同时保留对游戏操作的决定权。本文是后续接口设计，不表示目前已实现 TAS 导入或兼容执行。

## 显式选择格式

现有 `act` 按键含义保持不变。后续增加显式的 TAS 输入格式选择，不按文件后缀猜测，也不在相同输入文本上自动切换解释。格式标识须随计划、模拟调用、工作区数据和运行恢复持久化。

`act`、计划文件与模拟器使用同一份语义规范；不支持的动作、命令或版本差异应明确返回，不能静默忽略。解析后的语义动作与原始 TAS 行号、输入段、帧偏移一并保留，便于定位差异。

## 对齐动作与绑定，不只替换字母

当前参考实现中，TAS 的 `J/K` 为两套跳键，`X/C` 为两套冲刺，`Z/V` 为两套蹲冲，`S` 为暂停，`O` 为确认；本项目第二冲刺为 `Y`，`C/B/P/N` 为独立菜单输入。具体含义仍须根据来源版本验证。

TAS 的游戏按键可能同时绑定菜单或交互功能，例如跳跃兼确认、冲刺兼取消。转换须保留同一帧实际产生的绑定信号，不能仅按当前场景选择其中一个功能；跨场景切换也必须成立。合并两个现有动作是否等价，要用原生输入更新验证，不能仅凭名称认定。

两套键保持各自按下边沿：交替按键、同帧双键、持续按住与松开分别处理。同帧双键不等于游戏执行两次动作。摇杆角度、幅度、死区与方向组合也属于输入语义，不擅自量化或补键。

## 保留逐帧时序

- 输入段连续执行时不自动插入松键；分批调用、观察与规划回放不应制造额外输入边沿。
- 动作因换房、死亡或输入节点截断后，以实际消耗帧数保存游标及未执行后缀，不能丢帧或重复输入。
- 明确游戏更新、加载、冻结帧、模拟器采样和章节计时的口径。对照基线时记录实际起点和计时边界。
- `Read`、重复段等展开保留来源和游标；`ChapterTime` 等成绩元数据不当作按键。
- `console`、`Set` 等配置或装载命令不是普通按键。需单独核验能力和授权，由 agent 显式请求，主控不借导入自动改设置、选关或传送。

## 验收方向

先比较原生虚拟输入信号，再比较同初态游戏轨迹。覆盖双键交替与同时按下、跨调用持续按键、菜单兼用绑定、场景切换、提前截断后续接、模拟与实机的一致性。存在差异时记录首个分歧帧、来源行、输入状态和游戏状态；不能只比较最终用时。

本次 1A 学习仍使用已保存的原输入基线，先核对并显式转换；轻量搜索候选只用于分析，不实际采用。不能把输入解释或初态差异当成超越 TAS 的证据。
