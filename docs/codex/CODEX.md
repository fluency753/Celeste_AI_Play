# Codex 开发与审查入口

仅适用于 Codex 在本仓库的代码贡献；项目通用规范见 [AGENTS.md](../../AGENTS.md)。其他开发 agent 无须读取或执行本文，不将本文传给试玩 agent。

## 工作流程

1. **设计**：新功能或结构整改先请独立子代理检查方案。明确受影响入口、状态的维护者、转换条件和失败责任；同一事实只保留一个权威来源，请求状态与实际状态可以分别记录。
2. **实现与复盘**：修复时确认错误为何产生、原验证为何漏检，并查找同类入口。若根因是重复规则或隐式交接，一并修正结构；无法安全合入的独立事项写入 TODO，标明剩余范围。不要仅增加特判或搬动函数。
3. **验证**：保留真实状态转换和消费者，覆盖受影响的正常、失败、超时重试及重复操作。检查 mock 没有预设关键流程成功；断言用户可见结果、计量和最终资源归属。涉及 agent 工具或多模态输出的改动，必须通过实际执行器和工具入口调用，并检查接收 agent 最终收到的结果，不能只靠自动化测试、内部对象或协议格式断言。工具拦截和失败场景须实际触发，检查原因、已执行范围和后续操作说明是否清楚；图片等多模态内容须确认到达对应输入通道且可识别，不能以 JSON、路径或编码字符串存在代替可见内容。涉及提示词理解、自主工具选择和恢复操作时，还须由独立试玩 agent 验证实际行为。验证使用隔离环境或获准的实机窗口，不连接或干扰在用主控；受条件限制未完成时，明确记录未验证范围，不能宣称已完成整体验证。
4. **独立复核**：新功能、缺陷修复和结构整改提交前，由未实现该部分的子代理审查最终差异及调用链。修正发现后再次复核；审查后新增改动也须重审，记录实际范围或版本。
5. **交付**：按改动规模说明行为、根因、结构调整、审查发现和验证边界；规则或接口改变时更新对应文档。验证报告分别说明自动化测试、实际工具调用与接收结果检查、独立 agent 试玩的覆盖范围和结果，保留可复查的结果证据；不以测试数量代替使用验证。独立审查不替代验证。

## 按影响选用的检查点

- **状态与资源**：沿实际消费者检查队列、游标和目标交接；区分请求、确认、停止及收尾完成。清理失败不能阻断本会话安全归还控制权；耗时后处理不继续占用游戏。
- **所有权与发布**：会话文件、容器、后台服务和录像分别校验所有权。所有权拒绝不能被清理兜底吞掉；部分落盘失败后重试须能补完，不能先缓存成功而跳过持久化。并发修改核对原子性与冲突处理。
- **能力与表示**：按真实工具登记和执行位置判断能力，核对配置、运行实例、提示词与界面的一致性；不要用一个执行器的限制推断另一个。
- **预算与时序**：区分单条、整批及并发预算，分配前计入临时副本；检查升级、恢复与高负载下的单位、时钟和降级行为。

- **模型输入与多模态**：检查最外层实际进入模型的工具结果与输入通道；MCP／适配层格式正确不证明最终正确。图片须做独立可识别内容的端到端检查，字符量、视觉 token、模型生成与累计计费分别统计。

## 专项复盘

修改导航、执行器能力、回放或录制时，按相关章节查阅 [Codex 状态边界与缺陷复盘](STATE_CONTRACTS.md)，核对历史触发链；不要求无关改动通读案例。
