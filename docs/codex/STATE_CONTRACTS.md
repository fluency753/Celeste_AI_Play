# Codex 状态边界与缺陷复盘

本文由 [CODEX.md](CODEX.md) 按相关改动引入，供 Codex 复盘自身的实现与审查问题，不约束其他开发或试玩 agent。记录导航、执行能力、回放及录像的状态边界；剩余工作见 [TODO](../../TODO.md) 和 [验收说明](../TODO_DETAILS.md)。

## 导航

恢复与选章目的不能共用含混布尔参数：`stop_at_chapter_select=True` 曾两次被误当成“载入后停住”，实际却会把刚原生恢复的正确 Level 归入需要退出的场景。名称 enter_save、默认会进章节、flag 又会退回地图，加上缺少明确载入后冻结入口，造成调用者误读。现将 load_save_and_freeze 与 open_chapter_select 分开命名，旧 True 调用执行前拒绝；首次章节场景截断覆盖普通和锁步加载帧，不能只等可操作或用宏返回时才冻结。菜单宏原来只取 obs，忽略 block 后仍空输入等待退出；现在共用完整结果检查，拒绝即终止并保留实际计量。主控所有者导航的临时许可属于连接作用域，不属于工具函数本身，不能给 agent 调宏顺便放权。

操作门禁修复后的权威边界：用户三项权限、任务地图/存档约束和临时退出许可分别维护。原 `allow_map_exit` 对整批输入生效，跨加载进入下一关后仍可退出；现在许可绑定原 Level/Session，每帧（含加载）观察离开并永久撤销。选关原先根据原始 C/TAS J 预判，误拦原生方向优先且不确认的复合输入；现在在真实 Start(checkpoint) 入口纯解析最终目标、在任何启动副作用前核验。回归安装生产钩子、执行真实面板更新与虚拟按钮，不以模拟“选关成功”代替调用链。策略构造/迁移/结果共用轻量契约，两个动作钩子仍各自在真实执行边界校验。

`orchestrator/navigation.py` 的 `ChapterNavigation` 维护当前段、待进入段、段内进度与切换状态。输入约束和入场确认读取同一目标；只有观测到目标 `Level` 且未结算时才确认入场；检查点表已知时还要求起始房间匹配，确认后才消费队列。失败保留待进入目标。`GameSession` 负责桥接操作、统计和持久化，自动菜单与 agent 输入共用确认入口。

原先多个字段和两条选关路径各自组合状态，把上一章结算留下的地图字段误当成新章入场。测试只模拟“选关成功”不能覆盖这种交接，回归现在经过实际确认入口，覆盖结果页残留、错误起点、地图续跑及同章重进。旧属性是同一状态的代理，不能重新成为独立数据源。

## 执行器能力

章节重置门禁的根因：允许底层菜单按键不等于允许任意章节重置，旧入口只核验选关 SID/存档，不能阻止同章重启。仅在 act 前看观测也会漏掉同批打开菜单、移动、确认。现在 GameSession 统一传运行策略，桥接在真实 TextMenu 导航后、确认回调前检查实际 Item；依据游戏源码处理复合键，不推测选择或一概拒绝。默认禁止，动态策略保存后通知会话；旧桥接失败关闭。原生回归执行生产 ILHook、真实菜单和虚拟按钮，Python 覆盖所有 step 调用者、退出工具及会话通知；契约见[章节重置门禁](../CHAPTER_RESET_GUARD.md)。

`orchestrator/execution.py` 集中声明模型客户端位置、工作区读写、程序执行位置及容器需求。CLI、准备、聊天、工具、提示词、配置预览及旧会话同步按所需能力消费。Codex 客户端在本机，工作区工具仍走容器；Claude host 没有这些工具。

原先 `runtime` 同时承担位置和权限含义，复制的条件把一种执行器的限制套到另一种。后果包括提示词否认实际工具、漏准备门禁，以及无工作区工具的聊天仍创建容器。能力测试保留真实配置解析、提示词与动态工具派发，只替换外部进程。

## 回放

`Playback` 的提交与关闭共用接收锁，显式作业交给唯一工作线程；线程负责已接管来源的最终清理。读取游标只在接受完整记录后推进，容量不足保留来源，完成时补处理尾部；计费身份跟随搜索来源，原生预测保留上游已记账属性。文件索引流式读取表头，不把全部轨迹提前装入内存。

原先把已读、已排队、已绘制和已计费混为同一进度；背压丢块、部分接管重试和关闭竞态分别造成漏画、重复计量和无人清理。回归保留实际工作线程和来源交接，检查覆盖及最终归属。内存限制区分原始轨迹体量与解码数组，不能把一个阶段的限额称为进程总内存上限。

## 录像与录音

活编码器接续与退出后恢复是不同路径，不能用“MKV 不能追加”解释缺少恢复入口。旧 `validate_resume` 只接收存活编码器，终态 manifest 又被当成没有旧录像，调用者反复使用 `--new-recording` 造成逻辑会话分散。现在普通续跑明确选择直接接续或退出后恢复，原目录和 session 身份保持，实际插件目录由恢复 ledger 统一维护。新编码器仅写唯一 attempt，源视频／PCM／CSV 取共同完整前缀后经 journal 发布累计产物；不能让 `-y`／`wb` 直接作用于旧文件，也不能将多个文件替换描述成整体原子提交。重试不重新拼已发布根目录，旧结果缓存不能抢先被当作新成片。失败状态不证明文件已经停止写入，须先确认采集终止及文件无写入者；正常重连优先沿用活编码器，不能为恢复功能顺手重建正常录制。

普通 Everest `ReloadMod` 会卸载 Mod 并重建当前房间；只把录音停止从 `Unload` 移走仍会丢失程序集静态对象、DSP 委托和连接。现在常驻 `CelesteAIRuntime` 独立拥有 IPC、时钟、输入门闸、录音 System 与共享 PCM，桥接逻辑仅交接无程序集引用的 JSON 快照。主控按动作锁准备、备份替换、普通加载、核验、完成交接，不停止或重建录像，不重放原动作。房间重建可改变玩家状态与手持物，主控刷新工作区及观测游标，清空持久化按住键，要求 agent 默认 observe 后再执行；重载前排队的动作即使之后已有新观测也必须拒绝。完成核心交接与完成主控输出刷新分别落盘，后者失败重试只补刷新；跨进程续跑不能恢复未完成重载留下的旧按键。

实机验证发现两处原生替身测试覆盖不到的 Everest 时序：初始化批次延迟应用 detour，不能在 Mod.Load 内把尚未安装的门闸当成最终失败；必须在接管和重载准备前检查已实际安装。冻结时在 MInput 后直接 return 又会阻断 MainThreadHelper 的组件调度，使普通 ReloadMod 无法进入维护场景。现在持有期间跳过场景更新与 DashAssist 分支，但执行场景交接与 Game.Components，另用常驻 Level.Update 门闸挡住加载器切入关卡的同帧更新。共享 HUD 心跳也由常驻核心在交接期间续写。原生测试替换 Loader 的成功只证明资源交接，不能代替真实普通加载、失败 DLL 卸载后同 lease 恢复或真实 OBS 编码器验证；覆盖边界见[桥接重载](../BRIDGE_RELOAD.md)。

按键绑定也是跨重载的常驻状态：Everest 注册任何模块都会调用 `Input.Initialize` 按玩家设置重建虚拟按键并恢复其他 Mod 快捷键，只把“已安装”标志留在核心里会让重载后的合成输入按玩家绑定解释。核心须在每次外部 `Input.Initialize` 之后（工作线程上的调用延到主线程、维护场景结束后）重新套用并报告实际生效的绑定；只发中立帧的重载验收发现不了这一点，验收要实际按抓与对话。重载快照与冻结之间不能释放游戏连接锁，录音计量以冻结后核心报告为准；只有未提交、原桥接仍挂接且场景帧号未变的交接可以撤销，其余情况明确要求重试或重启。

拆分核心时还须迁移端口的所有消费者。仅迁移 IPC／时钟监听、仍让 PCM 或 HUD 读旧桥接设置，会在两个配置恰好相同时被实机测试掩盖；现在运行端口统一取核心设置，验收故意保留错位的旧配置，再核对真实 OBS、音频共享内存和 HUD 都使用核心端口。

独立混音器原来固定加载七个官方文件，却种入所有实时事件，造成普通 Mod 事件在目标混音器中不存在；只跳过缺事件能保住录像，但不能算支持 Mod 音效。现在以实时 System 的 bank 集合为权威，用实际文件／内存来源或 Everest 的 ModAsset 匹配资源，两个录音 System 各自持有副本。源来源记录跨录像重建保留，源卸载／释放才清除；目标 System 不能重新注册成源。同步先于事件种入，源卸载／同 GUID 重载清理副本及缺事件缓存，不能只比较 GUID 认为内容没变。回归须关闭背景乐，分别验证真实 Mod 音效的两轨 PCM、ZIP 流释放与重建，不能用官方音乐有声掩盖 Mod 事件仍被省略。

`RecordingStop` 分开维护停止请求、确认采集停止和释放通知；编码完成另以插件终态为准。停止命令失败可重试，超时保留 pending，重复收尾不重复停止采集。终态持久化成功后才发布缓存。录像对象只用于一次采集。

录像所有权在接管、停止前、收尾轮询及归还控制前分别核对。`RecordingOwnershipError` 拒绝操作其他会话；本会话的清理或落盘失败则不能阻断安全归还。OBS 异步启动时，旧任务的非活动终态只是等待中的旧状态，不能被当成新任务成功或归属冲突。

`RecordingMixSnapshot` 只采集一次源总线／VCA／监听器状态，两条录音轨应用同一快照，后续 setter 继续镜像。显式本地暂停优先；未记录 setter 时，不能把祖先继承的暂停复制成子总线本地暂停。full 随全部成片帧推进，play 只随真实游戏帧推进，墙钟等待不推进录音。

这些问题的共同成因是状态责任和失败契约分散，而不只是漏写条件。此次独立交叉审查发现的二次问题也加入了回归，包括持久化失败后的缓存、错误类型混淆、异步启动旧状态及原生预测重复统计。

## 验证与边界

Bash 几何摘要丢头的根因是把“工具输出预览”放进通用执行结果中：`run_program` 静默保留最后 2000 字符，spinner 明细挤掉前面的边界、出口和玩家状态，且诊断等机器消费者也收到被截断的数据。现在原始执行结果与工具展示分开，首尾预览显式声明截断和完整文本路径，发布失败不伪造路径或改变执行结果。回归覆盖真实动态工具分发、机器 JSON 消费、Unicode 与超时部分输出；独立临时容器另验证完整文本往返、导入隔离和预置符号链接拒绝。现仍采用整流内存捕获，未设置输出字节／磁盘总额上限，不能将“预览有界”称为“捕获有界”；两个流的发布各有 20 秒超时，资源预算的后续范围见 TODO。

补齐灰尘眼睛时，将补画层级从水晶专属队列抽为统一视觉通道；多种补画各自按深度排序仍可能在同一原生实体边界相互错序，只有一个合并游标才能保证跨类型层级。眼睛不能复用灰尘主体 Render 的补画入口，否则会进入边缘掩膜。眼睛状态提取为可测试的只读计划，与真实 Eyeballs.Render 的绘制调用对照；混合邻居则对照真实初始化，避免为了看似连续而强改已有实体或忽略原生 Collidable 规则。

灰尘回放外形的遗漏来自把“实体能画出来”等同于“视觉初始化完整”：灰尘即使尚未执行镜头内的首次初始化，也会绘制中心贴图，因而原先只验证圆刺可见没有发现外围节点缺失。灰尘与水晶圆刺使用不同的组件与边缘通道，不能从其中一种的验收推断另一种完整。补画使用独立视觉计划，主体和原生边缘掩膜调用同一个 Render 钩子；生成规则与真实原生初始化对照，逐项验证种子顺序、几何和状态不变，GPU 效果另用真实录像核对。原生初始化还会添加眼睛实体并调用回调，不能为补画直接调用它或用临时修改碰撞的办法复用它。

剧情首次跳过交接的成因：把“可以作决定”与“当前对白已能接收确认”合并成一个节点，导致主控自动播放吞掉了 agent 的早期跳过机会；原验证只证明了停在完整对白、不会误按，没有验证从触发剧情到第一次交回的时延。现在 `storyDecision` 与 `storyInput` 分开，前者提供事实上的暂停尝试机会，后者仍只表示真实输入就绪。显式 `watch/advance/choose` 使用本次调用的仅播放策略，不继承自动模式的跳过／确认副作用；独立审查发现这项模式串扰后补入回归。原生检查直接执行真实 `StepJob`，确认暂停解锁的第一帧就截断，Python 保留 `act→自动推进→watch` 的真实消费者链；可控教学与 TAS 的控制边界不变。

新增统一碰撞视图的成因复盘：`solids` 命名容易被理解为全部障碍，但实体固体另在 `entities`；地形又从叠加实体符号的 ASCII 展示反推，表示层可能遮掉真实地形。只提醒模型“看全数据”没有消除接口上的拼接负担。现在桥接从同一帧的真实 Grid／Collider 输出统一快照，来源覆盖与形状精度分开；Python 的各工具和工作区消费同一身份校验，实体每次替换，不跨帧补齐。测试以头顶实体砖、移动／消失、稀疏 Grid 和旧协议缺失为触发链。功能契约见 [统一碰撞视图](../COLLISION_VIEW.md)。

- Python：`python -m unittest discover -s calibration -p '*_test.py'`，隔离实际桥接、模型与进程。
- 原生音频：`LIFECYCLE_ONLY=1` 运行 `calibration/audio_mixer`，分别使用同步与 `ASYNC_SOURCE=1` 源，验证快照不可变、暂停继承、冻结重建及双轨冲刺／对白 PCM。
- 录制封装：`python -m calibration.recording_mp4_check`，执行生产 C 收尾逻辑与真实 FFmpeg。

自动化不代表已验收真实模型的自主决策、任意 MOD 地图或所有压力组合；本轮未启动试玩、连接在用桥接或替换已安装组件。Codex 的新增功能与后续修复按 [CODEX.md](CODEX.md) 执行成因复盘和独立最终审查。

## 几何信息密度与查询边界

Bash 首尾预览修复了静默截断，但默认对话表达仍把完整快照当成每次都应发送的数据。第一版又只针对超过固定数量的危险物归组，并把完整反射字段加回每个实例；只看 s1 的离线降幅，没有检查同帧 s2 的全部返回成本，后者碰撞部分反而从 20994 增为 24486 字符。完整数据、适合阅读的表达和跨调用变化是三个独立职责，不能靠扩大上下文或让模型多查几次补救。

现在原始工作区与精查保持完整，默认 room-context-v2 保留全部精确实例位置，共同属性和形状只定义一次；首次输出布局，后续输出完整替换对象的增删改。每个 server 独立维护 last_emitted，两阶段 prepare/commit，完成文字及图片构建后才提交；不能声称服务器知道模型已经收到或记住布局。默认 observe 重建基线，区域/玩家查询不更新基线。范围或 side 改变、失效后恢复及变化过大时重建，delta 带前后快照身份和所需形状定义；同名 roomChanges 替换外层房间字段，包括空值。

精选状态是稳定、无舍入、无按个数截断的独立投影，不承诺掌握所有机关语义；未知反射细节仍可查询。归组不代表机关行为相同或实心包围区域。回归覆盖全部实例几何还原、增删改、状态 false/0、同帧状态导致快照失效、查询不触桥接、图片失败不推进基线、剧情与动作共用变化链、原始工作区不变；独立审查发现的首次字段/后续字段映射歧义与触发器过滤重复已统一。历史快照测量和真实工具返回测量分别记录，不把离线对照当作实时验收或模型理解证明。

## 最终模型输入与图像通道

原生 MCP 返回合法 ImageContent、Codex 工具返回 inputImage，不等于模型最终收到图像。当前模型目录要求 code_mode_only，CLI 关闭 code_mode 也不能推断该模型不经过代码包装；工具图像在包装层变成 URL 字符串后，text(r) 将其打印成 Base64。旧验收停在适配层并统计原生文字，遗漏了最外层 custom_tool_call_output，因此文字压缩成功仍伴随每步约两万多 token 增长。应检查实际最终输入、模型可识别的图片以及完整工具链的累计成本，不能用中间层字符量证明上下文收益。

修复将可打印工具值与会话图像输入结构上分开，图像只用固定原轮次的 image 输入交付。动作、图像入队、文字返回串行；独立审查还发现“先捕获轮次，再等动作锁”会让旧轮次排队动作先执行后报错，故锁内执行前也检查轮次。发送失败保留动作事实、暂停且不重试动作或跨轮次补图；日志递归遮盖各别名中的 data:image URL。旧会话无需新增工具，加载新主控即可。

自动测试覆盖并发、换轮、暂停、发送失败和日志；显式真实模型检查使用生产 CodexRunner._request、临时线程、两张随机图片并故意 text(r)，核对原生 image 输入、最终文本无 Base64、随机码读对及同轮完成。原始数字不在文字提示中，不能凭接口确认替代视觉验收。该隔离测试不操作用户游戏；暂停中的真实会话只检查更新、录制接续及冻结，实际游玩 token 增速另在恢复后核对。
