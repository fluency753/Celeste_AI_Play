# Codex 状态边界与缺陷复盘

本文由 [CODEX.md](CODEX.md) 按相关改动引入，供 Codex 复盘自身的实现与审查问题，不约束其他开发或试玩 agent。记录导航、执行能力、回放及录像的状态边界；剩余工作见 [TODO](../../TODO.md) 和 [验收说明](../TODO_DETAILS.md)。

## 导航

`exit_level` 原来把“离开当前关卡”和“结束整次试玩”绑定：用户授权从 1A 返回地图进入 2A，agent 正常选用了这个工具，结果却清空队列并结束主控，记录 `completed=false` 仍不足以证明任务可继续。现默认 `finish_run=false` 只在返回地图权限下导航，保留目标、队列、计时与录像；仅明确结束整次时传 true。稳定选章／章节面板属于菜单控制状态，不因 auto 模式的 END_SCENES 兜底而结束，也不适用玩家操作最少帧限制。返回本身不能制造通关证据，初始原生观察刚出现的完成证据仍须正常提交。菜单失败可能已推进输入，须用原连接更新实际观测与计量，不重发退出；工具把继续／结束／停止目标及失败范围明确传给模型。

原验证只断言了退出后 `completed=false`、`done=true`，把错误的产品语义写成预期。新回归保留真实工具、菜单宏、确认菜单和导航，核验返回后仍能继续输入并实际进入目标，只有入场核验才消费队列；另覆盖显式整次退出、权限、重试、超时、真实完成证据和 auto 菜单。真实 Terra 接收证据为 `local/map-exit-receiver-20261029-135903/summary.json`，外部仅替换游戏 IPC 状态机，不代表真实 OBS 成片验收。Codex 已有线程会沿用旧动态工具参数和描述，只改 Python 不能完成迁移，须在宿主停止后用已有环境同步工具备份更新登记；不启动试玩、不接游戏。

等待进入下一章只描述导航目标，不表示当前场景的剧情已结束。以 pending 目标接回尚有对白的旧章节时，`watch/advance/choose`、普通观测和动作后的剧情处理仍须遵循真实播放／输入节点；不能因 `navigation.switching` 在进入判定前一律零帧返回。自动剧情模式仍保留换章截断，agent 模式不代选、未知和等待预算等边界不变。导航随后刷新的观测须保留同次调用已播放的文本历史，否则帧虽推进，模型却读不到中途文本。首次写盘必须保留 agent 的实际 pending 入场状态，不能硬编码 false；auto 启动已消费的入场请求不保存成待执行，防恢复时重进。回归保留真实导航对象、工具消费、播放结果及写盘后重新解析，独立模型另实际观看两句新对白并检查未知阶段不空推。

主控 Python 更新应复用统一维护脚本，不在每次部署时临时拼接进程扫描、HUD 查询、中断与启动。快速检查只读现有 HUD、共享内存和录制引用；更新分开核验请求确认、旧宿主退出、原录制及新宿主接回。HUD paused 不证明游戏 frozen：关卡保留活编码器要求冻结同帧，选章地图则正常关闭本段采集，跳过累计转码，并在恢复后核对原前缀计量，不能将两种边界混用。Windows venv 的启动包装 PID 与实际主控 PID 可能不同，须核验宿主、父 PID 并等待实际主控退出。启动回执不代表 ready，latest 也可能早于 run_state 发布；等待绑定唯一宿主。超时／回执未知接续同一交接，确定失败不永久阻断未来更新。在用主控只读检查，完整维护链路在隔离环境验证。

加载器类型不等于仍在自动加载。`OverworldLoader` 的 C 面／变体明信片在原生协程里等待输入；后台完成、卡片仍附着且可见时，Bridge 将其统一视为可冻结呈现，卡片移除后恢复自动加载。原先只改场景分类还不够：核心若按类型继续运行原加载器，就无法冻结，也永远等不到 ready。核心只须区分 prepare 原对象与新维护对象，同一谓词用于冻结、ready 和按键恢复；不加入剧情判断。还需沿 Python 的 END_SCENES、story_pending、watch／advance 和自动结算消费者验证，避免呈现动画被直接判作任务完成。

实际工具返回还必须追到真实终态：`Postcard.EaseOut` 的 `RemoveSelf` 仅入队，`Scene` 引用延迟到下一次更新才清除。只检查引用与 Visible 会把零透明度的待删卡片冻住，工具返回 unknown，测试收尾再补中性帧却能掩盖它。共享卡片事实须排除原生移除队列，正常 alpha=0 开场仍合法；DisplayRoutine 移除后的真实尾延迟可播放，但不复活 UI／输入。权威 loader wait 只中性等待到下一输入或地图，完成提交也不能绕过它；验收要求一次真实 advance 后自然抵达下一边界，禁止把测试修复输入计作产品通过。

让加载器提示开始消费显式输入后，还要防旧菜单输入跨界流入。菜单宏附 `menu_prompt`，原生卡片一附着便截断，包括后台尚未完成和开始时已在提示的情况；旧 C 未执行，结果携带当前观测与执行范围。普通 agent 的显式剧情操作不带此菜单专用截断。新增导航中断要同步 CLI、帧日志和维护等待消费者；主控／Bridge 必须一起更新，不能只测试新核心内部对象就宣称整体交接完成。

原生确认菜单的“是”不能作为动作身份：返回地图与重启章节在中文、英文等语言中同译，按译文依次匹配会把前者误判成后者。动作与安全项应核验当前按钮实际绑定的原生回调，确认动作读取该原生闭包的 `restartArea`，并校验回调所属场景；追加／替换回调不能沿用旧身份。原生回调身份可在桥接重载后重新识别，不将语义只存于构造时的临时登记。原回归把 `Dialog.Clean` 结果伪造为不同键名，消除了现实中的译文碰撞，因而漏检；回归必须让两个确认显示相同文本，保留真实原生按钮、菜单分派和权限消费者，只替换退出副作用。

认证失败还须沿政策兜底继续审查：若未知按钮在已通关／主控离开授权下自动放行，把危险回调追加后变成 unknown 就反而能绕过权限。Level／IntroVignette 的未知菜单项仅在三个权限全开时放行；完成状态和当前关卡离开授权只作用于已认证的返回地图／保存退出，不作用于未知项或重启。地图等普通非关卡菜单仍按原有导航约定处理。

场景支持必须来自 Everest 实现，不能把主控尚无适配等同于游戏无法保存进度。非 Level 普通重载保留原对象，入场呈现可在原协程位置重载，无须隐式确认后才进入关卡。菜单平时会空闲推进，必须由 Bridge 先取得短暂维护冻结，再读取快照并原子交给核心；这个短暂冻结也有独立失败责任，准备结果未知先查询核心，核心 idle 才释放，反复断线不能丢掉未释放标记或等待阶段。所有场景保存中均等待原生外层保存协程，场景冻结不能挡住该协程。新增身份字段只核验旧快照已有的内容，避免旧版升级后永远不能接回。

重载应先核对 Everest 原生路径，不把“不是 Level”当作不能重载：AreaComplete 会被普通 ReloadMod 原样保留，Level（含 transitioning）才走房间重建。Bridge／主控分别维护身份和 UI 核验；核心只执行调用方声明的替换／保留通用引用条件，保留模式绑定整个 lease 的原对象且不允许重试降级。普通重载必换场景的旧假定会让结算永远等不到 ready，属于必须驻留修正的交接基础设施，并非把游戏策略重新放入 Runtime。

自动加载请求先停在 `reload_ready` 零输入边界，再取新的冻结快照；不能使用旧 hello 与新 observe 的组合直接判定“未冻结”。这个维护截断覆盖加载到关卡、结算或菜单，避免旧 chapter_loaded 漏掉结算而多推一帧；上层再决定目标适配，不确认剧情／结算。加载等待超时须取消原等待，套接字读取超时后只重连原所有者处理取消，不重发 step；无 lease 的等待失败重试从新边界开始，保留原更新请求与暂停状态。任务 done 与连接释放分开判断，完成任务的维护重载不恢复模型。

维护退出不能把 `LevelEnter` 一概当作不能保存的阻断：原生既包含自动入场，也可能显示需确认的明信片。维护等待只发单帧中性输入，剧情输入出现即停；自动加载器只观测，累计输入帧、加载帧和观测帧差，并设墙钟期限。`Level.CanPause=false` 还可能来自死亡、暂停锁或屏幕擦除，不能反推成转场；Bridge 只读报告 `screenWipe`，等待只认已知加载场景、`transitioning` 或该明确事实。每次新观测都重验槽位；已暂停的菜单和可暂停的剧情仍走原有保存退出，不增加无必要的剧情拒绝。

“没有关闭进程的专用 RPC”不代表主控不能退出游戏：正常路径是保存退出后按原生主菜单的“退出游戏”。维护宏依据实际按钮与方向邻接导航，按键确认和方向分开；桥接只读报告 PID 与菜单，Runtime 不增加退出策略。最后确认可能先断 IPC，不能把断线等同于成功，须提前持有原进程句柄并确认正常退出；不自动重发确认、不强杀。录制的 capture_stopped 仅表示停止采集，后续仍经桥接轮询编码器；退出安排在编码器终态确认之后、累计发布／转码之前，且先持久化 finishing，以免耗时后处理占用游戏或过早关闭丢失 OBS 状态。

PICO-8 是独立 Emulator 场景，现有截图、冻结与状态读取只支持本体关卡，不能因输入按钮可复用就认定小游戏可玩。Bridge 1.4.0 在 PicoConsole.OnInteract 和 OuiMainMenu.OnPico8 两个真实入口的任何副作用前拒绝 agent 动作，保留当前场景；StepJob 报告触发帧计量、未执行余量和 unsupported_scene_blocked，主控禁止因失控观测再自动等待，工具说明小游戏身份、暂不支持及继续本体关卡。手动输入无活动 job 时放行；Runtime 不增加游戏策略。原生检查执行真实入口钩子核验场景、暂停锁、解锁设置及菜单焦点未改变；接收检查回放原生拒绝结果，经生产工具和真实模型确认原因、执行范围与不重试行为，不将该边界验收宣称为整段实机试玩。

agent 剧情模式不能用“没有识别到输入节点”推断“动画仍在播放”。3A 旧纸在普通对白确认后进入 `MemoPage.Wait`，桥接只识别 Textbox／教学／明信片，主控因 `inCutscene` 和 Dummy 标记空推 18,000 帧，连带阻塞后续观测。现由桥接独立报告 `storyPlaybackState`，按实际叶协程识别已知播放与旧纸输入；未知或缺字段立即交回，每次调用的等待共用 600 帧预算。拒绝也须保存新观测、报告已执行范围，且以 MCP ToolError 透传，避免模型只收到泛化错误。此前对白替身没有独立的输入型界面，且未检查实际接收模型看到的失败信息；原生真实 Memo 协程／StepJob、私有游戏翻页及独立模型接收分别补齐这些边界。

收紧未知剧情后还须验证已支持剧情的完整生命周期。序章开场、奶奶走位、对白触发回调和鸟出现前的坍塌动画未纳入原生播放识别，真实 Terra 的 `watch` 在没有输入节点时零帧返回，随后因工具提示仍推荐观看而选择跳过。原 Python 测试提前写入 `playing`，只能证明消费者，不证明 Bridge 真能识别。修复沿真实协程栈核验原生所有者和当前执行叶，不以 Dummy、`InCutscene` 或整段外层协程替代输入判断；教学的方向加冲刺等待必须交回，Textbox 的未知子协程也不能由外层动画掩盖。开场淡出完成与回调切场景之间仍有原生一帧，玩家入场也有自动协程，验收必须从开场自然抵达可操作状态，并从奶奶、鸟的自动阶段抵达真实输入边界，不能补裸空帧掩盖中途停住。可尝试跳过和可自动播放是两种不同事实，观测与自动推进提示均读取同一播放分类。

同类入口检查不能止于序章：官图 CS 类型、NPC 对话和共享动画的真实 yield 链一同核查。原生方法登记须包含静态迭代器；辅助镜头和 NPC 背景循环不能作为主剧情授权，Everest 手动驱动的原始 ending 迭代器须解开包装后再判输入。照片、呼吸、诗页和片尾确认优先于外层主协程；原生混合协程按已核实的恢复状态区分输入与自动播放，未知状态停止。这些状态依赖当前 Celeste 1.4.0.0／Everest 实现，升级游戏程序集后须复核原生检查，不承诺第三方 Mod 的任意剧情自动播放。

逐段分类通过仍不足以证明连续播放：真实奶奶对白在 `EaseOpen` 完成后被误停，因为 `Coroutine.Update` 只弹出子协程，父协程下一帧才恢复，其 `Current` 仍指向已经完成的子迭代器。现在仅接受已核原生类型、同一所有者且确实结束的子协程交接；未知／错所有者不放行。头像 Sprite 在对白协程之后更新，动画刚结束时也须允许原生父状态恢复；明信片计时刚归零仍属于当前已知延时。连续回归用真实 `Coroutine.Update` 走完开闭、等待、原生确认和父恢复，不能只注入“已完成”。界面移除还需区分逻辑与绘制：待删实体不再作为输入、播放阻断或 UI 事实，当前帧原生仍绘制的闭幕界面则继续纳入截图，不机械共用同一个存活谓词。

消费者也不能把可操作性当成自动剧情的反面：鸟教学前的原生慢动作已经播放，玩家仍短暂为 Normal；旧提示说无需观看，旧 `watch` 又在权威播放判断前直接退出。显式观看现在在该交叠阶段逐帧推进且移除“起始已可操作”的停止条件，每帧重核播放与输入，不以一批 30 帧越过剧情结尾。普通观测／动作的可玩交接不变，避免修复显式观看时重新引入隐式代玩。另核每次调用的预算续看入口：原生入场可能没有 `InCutscene` 标记，权威 `playing` 仍须允许下一次 `watch`，不能只验证两次预算恰好覆盖的幸运路径。

教学动画达到 Scale=1 也不代表原生父剧情已经监听按键：GUI 更新发生在相关协程之后，还须经历 ShowTutorial 完成弹出及父剧情恢复。序章只在绑定的真实 GUI 对应父协程进入方向与 Dash 等待后报告 `tutorial`；连续回归先证明早按丢失，再验证首次报告就绪后原生确实接受 Dash。实机验证也必须实际发送一次该输入，不能仅以“看到教学提示后停下”宣称可操作边界正确。

剧情输入可执行也不代表剧情内容可见：`GameplayBuffers.Level` 不含原生 HUD，照片、纸页与呼吸目标框会缺失。现在仅在真实剧情 HUD 出现时，读取本游戏已经绘制的视口，在帧条及桥接 HUD 之前采图；不再重绘场景，普通世界／显式 gameplay 缓冲沿用原路径。请求绑定场景对象与帧号，错帧或读图失败明确无图并保留已执行动作，不能静默换成不含界面的旧缓冲；图片保持原生高分辨率，同房操作也返回剧情图。最终模型接收仍须验证具体可识别内容，不能仅检查 PNG 尺寸或 native ImageContent。

采图不能只验证一个场景的渲染入口：`IntroVignette` 在 `Engine.RenderCore` 的目标上直接绘字，但 `Level.Render` 先绘制多个离屏缓冲，再独立切回屏幕合成世界与 HUD。只接管前一处会使开场图通过、关卡对白图全部缺失，真实奶奶接收验证暴露了这个差异。两处原生屏幕赋值均核唯一点及前后渲染锚，改为 Bridge 复用目标，绘制一次后按原视口回贴；目标保留原后备缓冲的格式、深度和采样能力，解绑读回时保留内容。避免已知 FNA3D 后备缓冲暂存泄漏，挂钩失败只报告无图，不破坏正常游戏绘制。

恢复与选章目的不能共用含混布尔参数：`stop_at_chapter_select=True` 曾两次被误当成“载入后停住”，实际却会把刚原生恢复的正确 Level 归入需要退出的场景。名称 enter_save、默认会进章节、flag 又会退回地图，加上缺少明确载入后冻结入口，造成调用者误读。现将 load_save_and_freeze 与 open_chapter_select 分开命名，旧 True 调用执行前拒绝；首次章节场景截断覆盖普通和锁步加载帧，不能只等可操作或用宏返回时才冻结。菜单宏原来只取 obs，忽略 block 后仍空输入等待退出；现在共用完整结果检查，拒绝即终止并保留实际计量。主控所有者导航的临时许可属于连接作用域，不属于工具函数本身，不能给 agent 调宏顺便放权。

操作门禁修复后的权威边界：用户三项权限、任务地图/存档约束和临时退出许可分别维护。原 `allow_map_exit` 对整批输入生效，跨加载进入下一关后仍可退出；现在许可绑定原 Level/Session，每帧（含加载）观察离开并永久撤销。选关原先根据原始 C/TAS J 预判，误拦原生方向优先且不确认的复合输入；现在在真实 Start(checkpoint) 入口纯解析最终目标、在任何启动副作用前核验。回归安装生产钩子、执行真实面板更新与虚拟按钮，不以模拟“选关成功”代替调用链。策略构造/迁移/结果共用轻量契约，两个动作钩子仍各自在真实执行边界校验。

`orchestrator/navigation.py` 的 `ChapterNavigation` 维护当前段、待进入段、段内进度与切换状态。输入约束和入场确认读取同一目标；只有观测到目标 `Level` 且未结算时才确认入场；检查点表已知时还要求起始房间匹配，确认后才消费队列。失败保留待进入目标。`GameSession` 负责桥接操作、统计和持久化，自动菜单与 agent 输入共用确认入口。

原先多个字段和两条选关路径各自组合状态，把上一章结算留下的地图字段误当成新章入场。测试只模拟“选关成功”不能覆盖这种交接，回归现在经过实际确认入口，覆盖结果页残留、错误起点、地图续跑及同章重进。旧属性是同一状态的代理，不能重新成为独立数据源。

## 执行器能力

会话配置属于目标会话，不能从当前 HUD 锚点复制整份配置再逐项覆盖：字段白名单漏掉 `sim_assist` 时，新准备的线程会被要求提供旧运行才启用的模拟工具。聊天目录现以源会话完整状态为准（缺失字段也不继承），仅展示统计按原 HUD 约定沿用当前运行。Codex 的动态接口在初建线程时固化，按准备时配置裁剪接口又会使后续试玩开启模拟辅助或直播时缺少工具；现统一登记完整接口，执行时再按当前配置与准备／聊天／暂停阶段检查，描述生成使用独立配置副本，不复用会修改游戏会话基线的真实服务器。旧验证只比较同配置的准备和试玩，没有覆盖来源配置冲突、缺省字段与阶段能力变化；新增回归及隔离真实模型接收验收分别检查配置归属、接口连续性和实际拒绝理由。旧线程缺接口继续要求停宿主后显式迁移，不以自动改写在用线程掩盖问题。

章节重置门禁的根因：允许底层菜单按键不等于允许任意章节重置，旧入口只核验选关 SID/存档，不能阻止同章重启。仅在 act 前看观测也会漏掉同批打开菜单、移动、确认。现在 GameSession 统一传运行策略，桥接在真实 TextMenu 导航后、确认回调前检查实际 Item；依据游戏源码处理复合键，不推测选择或一概拒绝。默认禁止，动态策略保存后通知会话；旧桥接失败关闭。原生回归执行生产 ILHook、真实菜单和虚拟按钮，Python 覆盖所有 step 调用者、退出工具及会话通知；契约见[章节重置门禁](../CHAPTER_RESET_GUARD.md)。

`orchestrator/execution.py` 集中声明模型客户端位置、工作区读写、程序执行位置及容器需求。CLI、准备、聊天、工具、提示词、配置预览及旧会话同步按所需能力消费。Codex 客户端在本机，工作区工具仍走容器；Claude host 没有这些工具。

原先 `runtime` 同时承担位置和权限含义，复制的条件把一种执行器的限制套到另一种。后果包括提示词否认实际工具、漏准备门禁，以及无工作区工具的聊天仍创建容器。能力测试保留真实配置解析、提示词与动态工具派发，只替换外部进程。

## 回放

Runtime 1.0.2 曾把“剧情／死亡／暂停可能丢失临时状态”变成核心的硬拒绝，并持有 Session、SID、房间、存档及章节计时来核验，导致维护规则调整也需要更新核心。1.0.3 删除这些游戏策略与字段：Bridge 导出／导入身份快照，主控在 finish 前核对实际观测，Runtime 仅透明传递字符串并维持资源、帧号和加载生命周期。普通房间重建无法保留的状态明确记录为维护语义，不据此一刀切阻止。原生回归必须调用真实 Bridge Import 验证错身份，不能在 fixture 里复制比较规则来掩盖校验搬移后的缺口。

`Playback` 的提交与关闭共用接收锁，显式作业交给唯一工作线程；线程负责已接管来源的最终清理。读取游标只在接受完整记录后推进，容量不足保留来源，完成时补处理尾部；计费身份跟随搜索来源，原生预测保留上游已记账属性。文件索引流式读取表头，不把全部轨迹提前装入内存。

原先把已读、已排队、已绘制和已计费混为同一进度；背压丢块、部分接管重试和关闭竞态分别造成漏画、重复计量和无人清理。回归保留实际工作线程和来源交接，检查覆盖及最终归属。内存限制区分原始轨迹体量与解码数组，不能把一个阶段的限额称为进程总内存上限。

## 录像与录音

自动停止条件触发、游戏仍冻结、录像已经关闭是三个独立事实。一小时目标原来虽已正确中止工具和模型，但收尾沿用普通结束的 `deactivate` 回调，停止录像后交还控制，导致无人操作的关卡继续运行。仅断言 `session.done` 和模型收到停止原因，遗漏了最外层 `finally` 的资源归属。主控现以单一结束策略区分普通交还、自动目标冻结并收尾、显式中断冻结并保留活录像；不能把保留冻结等同于 `Recorder.retain()`。冻结决策必须在任何回放／直播／服务清理前写入，清理异常也不能让外层关闭连接时解冻。普通用户停止和全局预算结束仍沿原语义，菜单按其冻结配置处理。

回归保留真实 `_run_session → _run_connected_session → Recorder.stop/RecordingStop → GameSession.close`，仅隔离桥接／OBS、模型调度、HTTP 和媒体进程；核验成片终态、冻结门闸、帧号、关闭套接字、`summary.game_released=false`、重复收尾及原录像恢复。覆盖停止请求失败、编码器超时、后处理和回放关闭异常。独立真实 Terra 经生产工具链收到到时拒绝并停止重试，随后同一生产收尾链完成，证据 `local/goal-freeze-receiver-20261029-130301/result.json`；Bridge／OBS 为零媒体帧状态机，不宣称真实 OBS 成片验收。用户实际游戏另通过维护连接重新冻结并核验固定帧，原摘要备份后记录维护重新接管事实，未恢复试玩。

维护续跑不应等待最终派生物：关闭本段编码器后保留 finishing 与 postprocess_pending，累计发布和纯享转码留到最终正常停止，避免为下一主控制造并发媒体写入。采集关闭与成片完成分开；已确认的终态可在传输关闭后离线补完，不重新查询已退出的游戏。正常完成凭据绑定真实采集目录、会话 ID、媒体哈希与计量，才允许跳过完整解码；包时间戳、CSV 或 PCM 不符仍严格恢复。不能拿 finished 字样为旧录像补凭据，不能用 mock 媒体成功代替真实 B 帧与双轨拼接验收。

活编码器接续与退出后恢复是不同路径，不能用“MKV 不能追加”解释缺少恢复入口。旧 `validate_resume` 只接收存活编码器，终态 manifest 又被当成没有旧录像，调用者反复使用 `--new-recording` 造成逻辑会话分散。现在普通续跑明确选择直接接续或退出后恢复，原目录和 session 身份保持，实际插件目录由恢复 ledger 统一维护。新编码器仅写唯一 attempt，源视频／PCM／CSV 取共同完整前缀后经 journal 发布累计产物；不能让 `-y`／`wb` 直接作用于旧文件，也不能将多个文件替换描述成整体原子提交。重试不重新拼已发布根目录，旧结果缓存不能抢先被当作新成片。失败状态不证明文件已经停止写入，须先确认采集终止及文件无写入者；正常重连优先沿用活编码器，不能为恢复功能顺手重建正常录制。

普通 Everest `ReloadMod` 会卸载 Mod 并重建当前房间；只把录音停止从 `Unload` 移走仍会丢失程序集静态对象、DSP 委托和连接。现在常驻 `CelesteAIRuntime` 独立拥有 IPC、时钟、输入门闸、录音 System 与共享 PCM，桥接逻辑仅交接无程序集引用的 JSON 快照。主控按动作锁准备、备份替换、普通加载、核验、完成交接，不停止或重建录像，不重放原动作。房间重建可改变玩家状态与手持物，主控刷新工作区及观测游标，清空持久化按住键，要求 agent 默认 observe 后再执行；重载前排队的动作即使之后已有新观测也必须拒绝。完成核心交接与完成主控输出刷新分别落盘，后者失败重试只补刷新；跨进程续跑不能恢复未完成重载留下的旧按键。

实机验证发现两处原生替身测试覆盖不到的 Everest 时序：初始化批次延迟应用 detour，不能在 Mod.Load 内把尚未安装的门闸当成最终失败；必须在接管和重载准备前检查已实际安装。冻结时在 MInput 后直接 return 又会阻断 MainThreadHelper 的组件调度，使普通 ReloadMod 无法进入维护场景。现在持有期间跳过场景更新与 DashAssist 分支，但执行场景交接与 Game.Components，另用常驻 Level.Update 门闸挡住加载器切入关卡的同帧更新。共享 HUD 心跳也由常驻核心在交接期间续写。原生测试替换 Loader 的成功只证明资源交接，不能代替真实普通加载、失败 DLL 卸载后同 lease 恢复或真实 OBS 编码器验证；覆盖边界见[桥接重载](../BRIDGE_RELOAD.md)。

按键绑定也是跨重载的常驻状态：Everest 注册任何模块都会调用 `Input.Initialize` 按玩家设置重建虚拟按键并恢复其他 Mod 快捷键，只把“已安装”标志留在核心里会让重载后的合成输入按玩家绑定解释。核心须在每次外部 `Input.Initialize` 之后（工作线程上的调用延到主线程、维护场景结束后）重新套用并报告实际生效的绑定；只发中立帧的重载验收发现不了这一点，验收要实际按抓与对话。重载快照与冻结之间不能释放游戏连接锁，录音计量以冻结后核心报告为准；只有未提交、原桥接仍挂接且场景帧号未变的交接可以撤销，其余情况明确要求重试或重启。

拆分核心时还须迁移端口的所有消费者。仅迁移 IPC／时钟监听、仍让 PCM 或 HUD 读旧桥接设置，会在两个配置恰好相同时被实机测试掩盖；现在运行端口统一取核心设置，验收故意保留错位的旧配置，再核对真实 OBS、音频共享内存和 HUD 都使用核心端口。

独立混音器原来固定加载七个官方文件，却种入所有实时事件，造成普通 Mod 事件在目标混音器中不存在；只跳过缺事件能保住录像，但不能算支持 Mod 音效。现在以实时 System 的 bank 集合为权威，用实际文件／内存来源或 Everest 的 ModAsset 匹配资源，两个录音 System 各自持有副本。源来源记录跨录像重建保留，源卸载／释放才清除；目标 System 不能重新注册成源。同步先于事件种入，源卸载／同 GUID 重载清理副本及缺事件缓存，不能只比较 GUID 认为内容没变。回归须关闭背景乐，分别验证真实 Mod 音效的两轨 PCM、ZIP 流释放与重建，不能用官方音乐有声掩盖 Mod 事件仍被省略。

`RecordingStop` 分开维护停止请求、确认采集停止和释放通知；编码完成另以插件终态为准。停止命令失败可重试，超时保留 pending，重复收尾不重复停止采集。终态持久化成功后才发布缓存。录像对象只用于一次采集。

录像所有权在接管、停止前、收尾轮询及归还控制前分别核对。`RecordingOwnershipError` 拒绝操作其他会话；本会话的清理或落盘失败则不能阻断安全归还。OBS 异步启动时，旧任务的非活动终态只是等待中的旧状态，不能被当成新任务成功或归属冲突。

`RecordingMixSnapshot` 只采集一次源总线／VCA／监听器状态，两条录音轨应用同一快照，后续 setter 继续镜像。显式本地暂停优先；未记录 setter 时，不能把祖先继承的暂停复制成子总线本地暂停。full 随全部成片帧推进，play 只随真实游戏帧推进，墙钟等待不推进录音。

这些问题的共同成因是状态责任和失败契约分散，而不只是漏写条件。此次独立交叉审查发现的二次问题也加入了回归，包括持久化失败后的缓存、错误类型混淆、异步启动旧状态及原生预测重复统计。

## 验证与边界

隔离实例的验收也须验证进程归属。测试宿主返回 0 不代表其 `finally` 已成功关闭游戏；片尾暂不能打开暂停时，清理错误曾留下旧实例占端口，下一轮虽启动新 DLL，却连回旧进程并误报输入缺陷。无效归因撤销，部署前确认旧进程真正退出，连接时将启动 PID、TCP 端口所有者、`hello.process_id` 和内存加载模块 MVID 与待测文件元数据比对，清理另以原进程退出状态确认。多项场景与多候选的证据分别记录，不能将错误实例的结果计作新候选通过。

纯享版曾把所有游玩区间线性相加成一个 `select` 表达式，116 段时触发 FFmpeg 解析深度限制；无条件改用旧参数重试又以“不支持参数”掩盖原错。现保留文件传递滤镜，用平衡加法树限制解析深度，仅当本次 FFmpeg 明确不识别文件参数时回退。原有测试模拟 `_run` 成功，没有真正解析筛帧表达式；新增真实 FFmpeg 的 116／1024 段生产生成链，逐帧解码核验源帧身份及时间戳，另检查编码错误不重试、旧日志不污染本次判断、失败保留旧成片。该后处理验证不占用游戏或 OBS。

Bash 几何摘要丢头的根因是把“工具输出预览”放进通用执行结果中：`run_program` 静默保留最后 2000 字符，spinner 明细挤掉前面的边界、出口和玩家状态，且诊断等机器消费者也收到被截断的数据。现在原始执行结果与工具展示分开，首尾预览显式声明截断和完整文本路径，发布失败不伪造路径或改变执行结果。回归覆盖真实动态工具分发、机器 JSON 消费、Unicode 与超时部分输出；独立临时容器另验证完整文本往返、导入隔离和预置符号链接拒绝。现仍采用整流内存捕获，未设置输出字节／磁盘总额上限，不能将“预览有界”称为“捕获有界”；两个流的发布各有 20 秒超时，资源预算的后续范围见 TODO。

补齐灰尘眼睛时，将补画层级从水晶专属队列抽为统一视觉通道；多种补画各自按深度排序仍可能在同一原生实体边界相互错序，只有一个合并游标才能保证跨类型层级。眼睛不能复用灰尘主体 Render 的补画入口，否则会进入边缘掩膜。眼睛状态提取为可测试的只读计划，与真实 Eyeballs.Render 的绘制调用对照；混合邻居则对照真实初始化，避免为了看似连续而强改已有实体或忽略原生 Collidable 规则。

灰尘回放外形的遗漏来自把“实体能画出来”等同于“视觉初始化完整”：灰尘即使尚未执行镜头内的首次初始化，也会绘制中心贴图，因而原先只验证圆刺可见没有发现外围节点缺失。灰尘与水晶圆刺使用不同的组件与边缘通道，不能从其中一种的验收推断另一种完整。补画使用独立视觉计划，主体和原生边缘掩膜调用同一个 Render 钩子；生成规则与真实原生初始化对照，逐项验证种子顺序、几何和状态不变，GPU 效果另用真实录像核对。原生初始化还会添加眼睛实体并调用回调，不能为补画直接调用它或用临时修改碰撞的办法复用它。

剧情首次跳过交接的成因：把“可以作决定”与“当前对白已能接收确认”合并成一个节点，导致主控自动播放吞掉了 agent 的早期跳过机会；原验证只证明了停在完整对白、不会误按，没有验证从触发剧情到第一次交回的时延。现在 `storyDecision` 与 `storyInput` 分开，前者提供事实上的暂停尝试机会，后者仍只表示真实输入就绪。显式 `watch/advance/choose` 使用本次调用的仅播放策略，不继承自动模式的跳过／确认副作用；独立审查发现这项模式串扰后补入回归。原生检查直接执行真实 `StepJob`，确认暂停解锁的第一帧就截断，Python 保留 `act→自动推进→watch` 的真实消费者链；可控教学与 TAS 的控制边界不变。

新增统一碰撞视图的成因复盘：`solids` 命名容易被理解为全部障碍，但实体固体另在 `entities`；地形又从叠加实体符号的 ASCII 展示反推，表示层可能遮掉真实地形。只提醒模型“看全数据”没有消除接口上的拼接负担。现在桥接从同一帧的真实 Grid／Collider 输出统一快照，来源覆盖与形状精度分开；Python 的各工具和工作区消费同一身份校验，实体每次替换，不跨帧补齐。测试以头顶实体砖、移动／消失、稀疏 Grid 和旧协议缺失为触发链。功能契约见 [统一碰撞视图](../COLLISION_VIEW.md)。

- Python：`python -m unittest discover -s calibration -p '*_test.py'`，隔离实际桥接、模型与进程。
- 原生音频：`LIFECYCLE_ONLY=1` 运行 `calibration/audio_mixer`，分别使用同步与 `ASYNC_SOURCE=1` 源，验证快照不可变、暂停继承、冻结重建及双轨冲刺／对白 PCM。
- 录制封装：`python -m calibration.recording_mp4_check`，执行生产 C 收尾逻辑与真实 FFmpeg。

自动化不代表已验收真实模型的自主决策、任意 MOD 地图或所有压力组合；本轮未启动试玩、连接在用桥接或替换已安装组件。Codex 的新增功能与后续修复按 [CODEX.md](CODEX.md) 执行成因复盘和独立最终审查。

## 几何信息密度与查询边界

Bash 首尾预览修复了静默截断，但默认对话表达仍把完整快照当成每次都应发送的数据。第一版又只针对超过固定数量的危险物归组，并把完整反射字段加回每个实例；只看 s1 的离线降幅，没有检查同帧 s2 的全部返回成本，后者碰撞部分反而从 20994 增为 24486 字符。完整数据、适合阅读的表达和跨调用变化是三个独立职责，不能靠扩大上下文或让模型多查几次补救。

现在原始工作区与精查保持完整，默认 room-context-v2 保留全部精确实例位置，共同属性和形状只定义一次；首次输出布局，后续输出完整替换对象的增删改。每个 server 独立维护 last_emitted，两阶段 prepare/commit，完成文字及图片构建后才提交；不能声称服务器知道模型已经收到或记住布局。默认 observe 重建基线，区域/玩家查询不更新基线。范围或 side 改变、失效后恢复及变化过大时重建，delta 带前后快照身份和所需形状定义；同名 roomChanges 替换外层房间字段，包括空值。

精选状态是稳定、无舍入、无按个数截断的独立投影，不承诺掌握所有机关语义；未知反射细节仍可查询。归组不代表机关行为相同或实心包围区域。回归覆盖全部实例几何还原、增删改、状态 false/0、同帧状态导致快照失效、查询不触桥接、图片失败不推进基线、剧情与动作共用变化链、原始工作区不变；独立审查发现的首次字段/后续字段映射歧义与触发器过滤重复已统一。历史快照测量和真实工具返回测量分别记录，不把离线对照当作实时验收或模型理解证明。

## 最终模型输入与图像通道

原生 MCP 返回合法 ImageContent、Codex 工具返回 inputImage，不等于模型最终收到图像。当前模型目录要求 code_mode_only，CLI 关闭 code_mode 也不能推断该模型不经过代码包装；工具图像在包装层变成 URL 字符串后，text(r) 将其打印成 Base64。旧验收停在适配层并统计原生文字，遗漏了最外层 custom_tool_call_output，因此文字压缩成功仍伴随每步约两万多 token 增长。应检查实际最终输入、模型可识别的图片以及完整工具链的累计成本，不能用中间层字符量证明上下文收益。

修复将可打印工具值与会话图像输入结构上分开，图像只用固定原轮次的 image 输入交付。动作、图像入队、文字返回串行；独立审查还发现“先捕获轮次，再等动作锁”会让旧轮次排队动作先执行后报错，故锁内执行前也检查轮次。发送失败保留动作事实、暂停且不重试动作或跨轮次补图；日志递归遮盖各别名中的 data:image URL。旧会话无需新增工具，加载新主控即可。

自动测试覆盖并发、换轮、暂停、发送失败和日志；显式真实模型检查使用生产 CodexRunner._request、临时线程、两张随机图片并故意 text(r)，核对原生 image 输入、最终文本无 Base64、随机码读对及同轮完成。原始数字不在文字提示中，不能凭接口确认替代视觉验收。该隔离测试不操作用户游戏；暂停中的真实会话只检查更新、录制接续及冻结，实际游玩 token 增速另在恢复后核对。

## 续跑提示词的更新渠道

按钮消息的可编辑正文与控制事实必须分开：默认正文原先散落在 Runner、准备、取名和控制通知中，只开放稳定指南编辑并不能覆盖它们。现在通过消息目录统一按事件读取本机模板，来源及事实在正文外固定附加，真实用户留言不重标，恢复通知附到既有下一轮而不替换原留言。配置接口只对按钮消息开放在线保存，不能据此在线覆盖稳定指南。没有消息的按钮不额外触发模型；模板读取失败降级保留事实。

帧限有配置、实际执行和旧工具说明三处消费者。在线控制只改变当前模式动作上限，在动作边界先原子保存到 run_state.tuning 再发布配置，不调用会重置其他参数的整表 apply；恢复读取同一持久化值。旧描述不代表工具 JSON schema 有硬上限，实际计划每次按当前 cfg 核验，最新通知及 observe 同步报告范围。隔离真实 Terra 验收保留旧150描述，将配置改300后执行200帧，清空通知正文再降100仍收到来源和事实；超限请求文字拒绝且零推进，模型修正80帧成功。业务拒绝沿原协议以普通文本返回，不将其宣称为 native tool error。HTTP、实际 HUD 脚本及落盘失败另用确定性回归覆盖，未连接用户游戏或录制。

自动续轮与用户提出新任务应区分。旧模板从只有单章动作的早期主控沿用“本章未通关，继续 act”，原生执行器又追加“先解说”，没有标明发送者，既暗示了未经核验的状态，又收窄了模型下一步选择。现在正常续轮仅提示依据已有任务与当前状态继续，准备续轮保留未读资料要求，两入口都标注主控自动消息，真实用户输入不重标。回归保留生产 Runner 循环与最终输入发布，覆盖正常、准备和用户消息替换；Claude 用真实 stdio 子进程只替换外部执行文件。真实 Terra 验收确认可自行选择 Read 延续原只读任务，并辨识来源；底层仍为会话输入通道，不将文本标签宣称为协议角色变更。

只去掉续跑消息中的副本，仍会在每次启动的系统指令里重发全部操作规则。现在保留 `play_prompt` 作为完整指南的生成器，有工作区文件能力的执行器通过 `runtime_prompt` 接收当前任务、配置与版本索引，详细说明按原 PromptPart 分节持久化，内容哈希用于判断变化节；同会话版本未变不重读，新会话首次接手不能相信他人留下的已读标记。聊天与取名按需查阅，首次正式游玩再读全；无文件能力继续内联，指南不属于可屏蔽知识库，也不替代准备阶段。

发布和引用必须使用同一快照。独立审查发现发布后重新读取模板可能引用尚未发布的新路径，现将 `publish_guide` 返回对象直接传给实际启动提示词；Claude 为覆盖旧压缩快照的短恢复配置也在发布后用同一对象生成，网络／额度重试沿用该边界。指南目录原子发布并核验已有内容，路径冲突或发布失败不启动模型，不覆盖笔记。控制台分别显示实际启动正文和按需指南，实时控制消息与工具反馈优先于启动快照。真实 Terra 验收核对首次阅读、同版零重读、只读变化节、新会话接手及显式模拟遗忘后的局部补查；文件 IO 边界隔离，未连接在用游戏，未将模拟遗忘宣称为实际上下文压缩。

续跑规则的更新渠道须按执行器核验。`current_rules_note` 原本用于 Claude 压缩后的旧提示词快照，却被所有执行器共用，导致 Codex 已通过 `thread/resume.baseInstructions` 更新系统规则后，又在首条消息重复发送完整规则。第一轮修正仅让 Claude 保留快照副本，Codex 的恢复消息只说明状态与用户留言；追加章节也不再声称后附全文。原测试只断言 Claude 副本存在，缺少执行器分支与真实恢复接收检查；新增组合回归，并用生产 CodexRunner 新建、关闭 app-server、恢复同一隔离 Terra 会话，核验新系统规则及历史口令同时可读。模板整理合并重复的返回地图、剧情和异常处理说明，保留授权、额度、几何格式与结算边界；必需协议不迁入可屏蔽的知识库。变更在下一次启动时生效，不向运行中的试玩重复注入全文。

## 分章录像与隔离启动依赖

一段模型会话、一次主控运行、一次采集和一个逻辑章节录像不是同一生命周期。分章后当前片指针不能代表全部录像已收尾；恢复、控制台 pending、交还控制和公开 finish_saved 都须读取全章清单。换章意图先落盘，再启动；回执未知按原 ID 接回，准备但未请求的下一片可取消。旧片离线后处理不再触碰游戏或覆盖当前片指针。只在外层 act 检查换章会遗漏菜单宏、剧情和恢复中的底层 step，因此统一在发送 step 前检查，并在原生场景边界截断复合输入，显式告知 agent 剩余输入未执行。

视频节拍和 PCM 必须使用同一帧的采集决定。加载器上下文由本片实际经历的章节建立，冷启动解锁提示不能当作新章节；异常恢复可由已核验的非空媒体前缀恢复该上下文。只证明 F/N 协议正确不能宣称 OBS 最终像素编码通过；实际模型接收、原生游戏协议采集与真实 FFmpeg 分片计量分别记录覆盖范围。

隔离验收曾按扩展名排除全部 JSON，漏复制 Celeste.deps.json 与 Celeste.runtimeconfig.json，导致 Runtime Bootstrapper 报依赖库缺失。游戏启动描述、运行时目录和依赖文件必须完整保留，只隔离用户配置与存档；看到 Bootstrapper 进程不代表游戏成功启动。以实际游戏 IPC、PID 和加载模块核验后才能执行测试，并确认失败启动与最终游戏均已退出，不能干扰用户原实例。
