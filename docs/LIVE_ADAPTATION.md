## 给独立 GPT 发提示、暂停和继续

聊天编辑框、发送和暂停/继续按钮直接放在 HUD 底部，不另开聊天窗口；Enter 发送，Shift+Enter 换行，中文输入法选词不会误发。输入控件只在桌面/预览中显示，OBS 只显示公开内容。用户提示和 GPT 的公开回复会出现在气泡历史中。

HUD 底部“会话管理”提供新建并准备、断开后台、A 面章节选择和开始试玩。新建可填写名称，从模型下拉列表选择模型及推理强度，并保留当前 Fast 偏好；后台生成独立 agent 标签和 Docker 工作区，真实读取两份精简入门资料，不继承旧聊天或旧笔记。准备过程由独立后台宿主执行，HUD 显示状态；完成后自动接入仅聊天的待命会话，保留旧会话供下拉切回。准备或接入失败时保留原选择并尝试恢复原聊天。

模型下拉框经 `/api/models` 读取 Codex app-server 的 `model/list`，显示名称与提交标识分离，不再要求手输。列表按官方协议使用隐藏标记、输入模态和每模型推理强度过滤；强度仅开放当前执行器支持的交集。列表缓存 5 分钟，刷新按钮可立即重新读取。首次选择优先保留当前模型及兼容的推理强度，后续切换保留兼容的已选强度。读取失败时提示重试并禁用新建，其他会话控制可继续使用；创建前再次校验所选模型与强度，失败发生在释放旧聊天之前。实测接口返回 7 个模型，非法模型请求返回 400 且原 agent 保持连接。包含目录过滤、分页和失败关闭、并发缓存、非法选项不释放旧会话的回归共 96 项通过。模型目录可能是服务的缓存/内置清单，实际访问权限仍以推理请求为准；不读取或复制登录凭据，不为读取列表创建线程。协议参考：https://learn.chatgpt.com/docs/app-server#models 。

“开始试玩”是单独操作，仅对新准备的会话开放：验证阅读证明、交还旧聊天宿主后进入指定 A 面章节，先保持暂停，点击“继续”才交给 agent 操作。“断开会话”只停止空闲聊天后台，历史、下拉条目和准备证明保留，可用“唤起 agent”重连。试玩中必须先通过现有“立即停止并保存”结束，再管理会话；正在回复或准备/接入时禁用冲突操作。本机普通聊天和真实游戏不会因为页面展开或新建准备而自行启动。

底部主按钮按完整生命周期统一生成文字、禁用状态和点击动作：准备中/接入中/启动中不能唤起；活动试玩显示暂停，暂停后显示继续，过渡时显示暂停中/恢复中。仅已结束且断开的会话显示唤起 agent，已准备但断开的会话显示连接 agent；连接失败显示未连接，避免保留过期的唤起或暂停文案。聊天待命和通关后已连接的聊天不提供游戏暂停动作。calibration.hud_controls_test 执行页面内实际状态函数，覆盖 17 个阶段和操作组合，包括旧聊天可唤起但新会话正在准备的交接状态。

底部 Fast 按钮旁提供“当前会话推理强度”下拉框，与新建会话的强度设置分开。选具体档位会手动固定，阻止 agent 自行调用 set_effort 改回；“推理：自动”撤回固定、恢复 agent 自行调整。选项从当前模型目录生成并在后台再次校验，旧主控没有 effort_control 能力时禁用。偏好按会话写入 SQLite，切换、唤起和续跑保留；准备后开始试玩也继承该手动设置。

切换不主动 turn/interrupt、不等待或取消动作锁；若正有模型轮次，使用已有 steer 通道请求当前工具结束后自然结束该轮，主控再按新档位继续。真实生效仅在 turn/start 成功返回后更新 metrics.effort，等待期间使用 effort_pending 展示“下轮生效”。空闲聊天修改不启动额外模型请求。测试覆盖空闲等待、活动轮次 steer 不打断动作、手动设置优先及恢复自动、turn/start 在途时保留用户最新选择。实际 HUD 接口已验证 high→等待 low，再恢复自动撤回请求，原会话、Fast 关闭状态和游戏均保持；未为测试推进游戏或强迫额外聊天回复。

## HUD 页面更新与解说历史

### 桌面与 OBS 独立布局

OBS 的 HUD 是独立浏览器来源，页面 URL 带 `?surface=obs`，卡片直接填满来源的内容区域，不再读取桌面窗口的坐标或宽高。默认来源 420×760，放在画布 (1480,40)，解除锁定；可在 OBS 中单独移动、缩放。修改来源属性的宽高会调整内容显示区域，字号保持固定；OBS 的变换缩放则像其他来源一样整体缩放。桌面缩放手柄和聊天控制区不会显示在 OBS。

本机保留“未命名 2”集合的“蔚蓝”场景，只迁移 HUD 来源；场景文件已备份到 local/obs-layout-backup/20261024-201844。OBS 空闲时重新启动读取迁移，确认选框直接包住 HUD。部署脚本只迁移旧整画布来源，后续保留 OBS 中自定义的位置、缩放和来源尺寸。本机继续使用 47792 的独立 HUD 服务。

桌面 HUD 是独立无边框窗口，不跟随游戏的位置、大小或可见性；游戏最小化、关闭或未启动时也不会自动隐藏。拖动顶部移动、拖动边缘调整大小，气泡区可以直接滚动。顶部提供“置顶”、最小化和关闭按钮，置顶开关会保存，移动或缩放不改变置顶选择。任务栏仍隐藏，双击托盘图标或托盘菜单“显示 HUD”可恢复最小化窗口；托盘同时提供最小化、置顶、恢复默认布局和关闭。关闭窗口只关闭桌面前端，不停止 agent、HUD 服务或 OBS。

正常窗口的绝对物理坐标、宽高与置顶偏好自动保存到 configs/local.hud-window.json（mode=window），最小化坐标不会覆盖正常位置。旧比例配置只作一次迁移，不再查询游戏客户区；本机迁移前额外保存了真实窗口坐标并备份旧配置到 configs/local.hud-window.before-independent.json。缩放手柄靠近时高亮。Ctrl+滚轮继续单独调整字号，每档 5%，范围 60%–180%，保存在 configs/local.hud-font.json 并共享到 OBS。窗口按钮与手柄仅在桌面显示，OBS 独立来源不受最小化、关闭或置顶影响。

桌面窗口最小高度为 260 像素，默认高度 760 像素，可按需自由缩小。所有可滚动区域（消息历史、底部控制区、展开的目标和输入框）统一使用细滚动条、灰蓝色滑块和透明轨道。

桌面置顶窗口和 OBS 的浏览器源可能保留旧页面，即使数据接口已改为独立 GPT，旧 JavaScript 仍会显示智能体标签或错误的来源。此次已重新加载桌面窗口，并在 OBS 中刷新 HUD 源。新版通过配置 `page_version` 检测后续页面版本变化并自动重载，不必重启游戏或智能体。

原先按游戏可见性隐藏/显示 HUD 的逻辑及重复置顶已移除。页面遇到暂缺 metrics 仍保留上次画面；静态文字仅在内容变化时更新，公开消息按 ID 增量更新。部署页面版本更新仍会重载一次。calibration.hud_window_test 验证窗口不自动显隐或重复移动、用户控制最小化/恢复/关闭/置顶、最小化时不覆盖正常布局，以及页面命令门禁；布局测试覆盖独立坐标、置顶持久化与屏幕边界恢复。

## 执行器公共接口（2026-10-25）

HUD 读取当前运行的 metrics.json、control.sqlite3 和 public_events.jsonl，不再读取本聊天的 Codex rollout 日志。模型与推理强度由执行器确认；无法取得的字段保持未知。公开事件仅包含消息、动作说明和压缩状态，不导出内部推理。

- orchestrator/session_controls.py：公共消息队列、暂停/继续、停止、目标更新/清除、剧情模式、推理强度偏好和心跳。执行器声明 RuntimeCapabilities，并实现验证强度、协议中断；支持活动轮追加输入时再实现 steer。
- Codex 使用 turn/steer 追加提示；Claude 没有该能力，通过官方 stream-json interrupt 控制请求结束当前轮，下一轮仅提交一次待投递消息。两个执行器均等待已开始的游戏工具结束后才确认暂停。Claude 中断协议参考 anthropics/claude-agent-sdk-python 的 _internal/query.py。
- Fast 是 Codex 的能力，Claude 不显示该开关，也拒绝相应控制请求。强度选项来自当前执行器的能力或模型目录，后端再次验证。Claude 不提供 xhigh。
- orchestrator/prompting.py：共享的新手/完整知识模式、剧情规则、恢复提示与限额模拟说明。Claude 也可显式使用 --knowledge explore --sim-assist；限额辅助必须运行在容器中。
- simulate 为公共 MCP 工具（Codex 映射为 celeste_simulate），与 observe/act/cutscene/exit_level 使用相同的阶段与暂停门禁；体力、预测上限和退款规则不因执行器改变。省略 candidates 只查询体力。
- orchestrator/telemetry.py：写入两种执行器共用的公开事件；HUD 用同一气泡历史显示消息和压缩状态。旧录像目录没有公共事件文件时，仍可读取原 Codex 公开事件；它只用于已有录像历史。

HUD 的新建、准备、取玩家名、切换、断开、重新唤醒和开始试玩均经 orchestrator/runtimes.py 的执行器接口调度，支持 Codex 与 Claude Code，包括通过 Claude Code 使用的 Anthropic 兼容提供方。后台 preparation 与 chat 为通用入口，不再通过 Codex 专用模块启动；orchestrator/lifecycle.py 根据执行器是否需要 MCP，托管不建立游戏连接的准备和聊天环境。

## 提示词与知识库

此前当前聊天直连的试玩没有完成沙箱的知识库准备流程，不能将那次运行标记为“已读知识库”。`--no-agent` 也没有 Claude Code 的 `Read` 结果流，现有按行审计不能自动应用到它。

独立 agent 应通过 `compose_prompt()` 接受同一套完整系统提示词，并保留 `KbStudy` 准备阶段，不传 `--no-study`。本机知识库需要完整阅读的清单由 `required_files()` 生成，包含规则、社区资料和模拟器说明；显示索引或让程序扫描文件不等于 agent 完成阅读。下一次试玩前必须先完成准备。

直播模式在 `live_zh.md` 中优先采用以下节奏：观察后立即公开解说；以 5–10 秒为更新目标；单次规划程序约 10 秒、最迟 15 秒返回；找到可行走法就先执行；长房间按安全落脚点分段；程序每 1–2 秒报告真实进度。10 秒提醒是后备提醒，不代表系统能够在模型尚未产生输出时生成新的解说。

## 直播与锁步录像的独立音频（桥接 0.12.0）

`configs/recording.json` 的 `audio_source: "game_nrt"` 启用第二个 FMOD Studio 系统。它读取本机安装的官方音频 bank，使用 `NOSOUND_NRT`，不打开声卡、不接系统扬声器，也不需要虚拟声卡驱动。原有游戏进程音频继续由 OBS 用于直播；`continuous_music: true` 时，agent 思考和规划回放期间直播 BGM 继续播放。

第二个系统镜像游戏音频事件的开始、停止、释放、cue、显式定位，以及每个游戏帧的参数、音量、音高、空间属性、总线与 VCA 状态。只有真实游戏帧调用一次同步混音，生成 800 个 48 kHz 立体声采样；思考和暂停期间不推进。规划回放的视频帧写入静音，不推进录像音乐，恢复真实游玩时音乐从原处继续。录像在中途启动时，以当时正在播放的事件与音乐位置作为起点，之后不追随直播音乐的位置。

桥接通过本机共享内存 `Local\\CelesteAIRecordAudio-47776` 发布 PCM，按 OBS 时钟令牌配对，而非按墙钟时间裁切。OBS 锁步插件直接将对应音频写入 `audio.wav`；该模式忽略 OBS 混音输入，因此锁步成片包含游戏 BGM、音效和环境声，不包含麦克风或桌面声音。普通 OBS 推流/录像仍使用用户原有音频配置。录像音频不作为可监听的 OBS 场景源，不能通过 OBS 监听意外发出第二份声音。
