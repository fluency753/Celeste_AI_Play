# 原生 GPT 与直播接入

这份文档说明为直播和原生 GPT 加入的功能：原生 GPT 执行器（经本机 Codex app-server）、探索模式、直播模式、可交互的网页 HUD（聊天、暂停 / 继续、会话管理、推理强度、目标与停止条件、剧情模式、存档选择）、录像专用的独立游戏声音、独立后台宿主，以及新建存档、剧情与退出关卡等游戏侧接口。部署步骤见 [DEPLOY.md](DEPLOY.md)，开关一览见 [README](../README.md#开关)。Claude 执行器速通正式运行与这些功能的边界见[最后一节](#与速通正式运行的边界)。

文中日期为北京时间。"实测"一行记的是开发中的实际验收，写明日期、模型与存档；存档名 `test` 是本项目的调试存档。

## 快速开始

需要先装好 Docker 与智能体镜像（GPT 生成的程序在镜像的零网络沙箱里运行），并在本机安装 Codex CLI、`codex login` 登录（见 [DEPLOY.md 4.11 节](DEPLOY.md#411-原生-gpt可选)）。

```powershell
.\start_gpt.ps1                                                                         # 准备：新会话读完必读资料（不连游戏、不录制）
.\start_gpt.ps1 -Play -Prepared runs\gpt-native\<准备目录> -Chapter 1 -Save <存档名> -SaveSlot <槽位>   # 用已有存档试玩
.\start_gpt.ps1 -Play -Prepared runs\gpt-native\<准备目录> -Chapter 0 -Save <新存档名> -CreateSave       # 新建存档，从序章开始
.\start_gpt.ps1 -Play -Resume runs\gpt-native\<运行目录>                                 # 续跑（沿用原存档、模型、知识范围与剩余章节）
```

- 不加 `-Play` 时只准备；`-Play` 必须给 `-Prepared`（新开一局）或 `-Resume`（续跑）之一。新开一局必须显式给 `-Save`，再给已有存档的 `-SaveSlot`，或用 `-CreateSave` 新建（只能从序章 `-Chapter 0` 开始）；`-Resume` 不接受存档参数。
- 默认探索模式（`-Knowledge explore`）；`-Knowledge full` 改用速通模式，准备和试玩两步都要写。推理强度默认 `-Effort medium`，`-Model` 留空时用 Codex 登录配置的默认模型。
- 试玩自动带 `--live --keep-obs-open --playback --continuous-music`，默认由独立后台宿主运行；`-Foreground` 在当前终端运行（调试用）。
- 也可以完全在网页 HUD 里操作：展开底部"会话管理"，新建并准备、选存档与章节、开始试玩。

## 原生 GPT 执行器

### 连接方式

`--engine codex` 通过本机 Codex app-server 的持久连接调用 GPT，复用本机已有的 ChatGPT 登录，不经过"Anthropic 接口 → OpenAI 接口"转换网关，也不把账号凭据传进 Docker。模型进程在宿主机；它生成的程序经 `celeste_bash` 在 Docker / bubblewrap 的零网络环境里运行（探索模式每次最长 15 秒，与提示词一致；速通模式与 Claude Code 的 Bash 相同，最长 10 分钟；都可以用可调参数 `explore_program_s`、`bash_max_s` 修改）。文件工具只允许读 `/workspace`、`/kb`、`/sim`，只允许写 `/workspace`。app-server 启动时关掉了宿主机的 shell、浏览器、联网搜索等内置工具，宿主工具配置为只读；检测到意外的宿主工具事件会停止运行。

HUD 直接使用 app-server 的公开消息、工具调用、tokenUsage 与 contextCompaction 事件。公开文字至多每 0.4 秒更新一次；模型没有输出时不能凭空生成解说。模型与推理强度采用服务器实际回报的值，上下文采用最近一次用量，不用累计输入量。内部推理正文不会进入 HUD 或事件日志。游戏工具由主控直接分发，只有一个桥接连接；规划回放和录制沿用同一个主控实现。

协议参考：[Codex app-server](https://developers.openai.com/codex/app-server/)。

### 准备与开始试玩

准备（`start_gpt.ps1` 不加 `-Play`，或 HUD 的"新建并准备"）不连接游戏，也不改变当前 HUD 显示的运行。准备会话阅读当前模式的必读资料并写 `/workspace/notes.md`，产生带逐行覆盖与 SHA256 的 `prepare_summary.json`；速通模式（full）另读模拟器说明。准备证明保存执行器、提供方、运行方式、请求的模型、会话 ID、文件摘要和实际读取覆盖。

开始试玩时恢复同一个原生线程，先核对身份、运行环境、知识范围与文件没有变化；准备超时不会放开游戏工具，`--quick-check`（只测索引读取与遥测）的结果不能用来跳过必读。工具在新建线程时全部登记，准备阶段仍拒绝游戏操作。未显式覆盖模型和强度时沿用准备结果。

Codex 恢复线程时检查该线程实际持久化的动态工具。旧线程缺少后来新增的工具（例如 `celeste_simulate`、`celeste_exit_level`）时，需要关闭相应功能或新建准备会话；不会悄悄改用 Bash 里的隐藏入口。旧工作区、存档和录像都保留。

### 默认采用探索模式

`start_gpt.ps1` 和新建的 `--engine codex` 运行默认使用探索模式。必读是 `kb/explore/` 的 README.md、basics.md（基本规则）、data.md（坐标与观测数据）与 tools.md（按键与工具）；`help/controls.md` 是选读的操作提示，随时可以读。目标是通过实际尝试探索并完成指定章节。知识库与提示词不提供技巧说明、实体说明、地图路线或隐藏内容位置，但不限制智能体用自己已有的知识，也不禁止高级技巧与自己写辅助程序（单次运行时长受 `explore_program_s` 限制）。

容器的 `/kb` 只挂载 `kb/explore/`，不提供 `/sim`。探索模式的工作区是 `workspaces/<标签>-explore`，容器与会话数据卷也与速通模式分开，防止读到旧的攻略笔记。切换知识范围必须新建准备会话，速通模式的 `--prepared` 或 `--resume` 不能混入探索模式。精确模拟器不开放；规划回放开关保持开启，只有提交了实际预测轨迹时才会出现回放。

实测（2026-10-24，Codex）：

- 速通模式（full）的准备会话（gpt-6.1-sol / medium）读完全部 30 份资料共 11,397 行，71 次工具调用；恢复同一线程后实际调用 `celeste_observe`，收到 1A 结算画面与截图，没有执行游戏动作。程序断网、凭据环境隔离、越界文件访问被拒绝均已实测。
- 探索模式的新会话完整读完 2 份必读资料，准备结束时上下文 11,007 token（窗口 475,000，约 2.3%），6 次工具调用；之前的准备会话结束时是 252,431 token，减少约 95.6%。

### 独立后台宿主

Windows 上 `start_gpt.ps1 -Play` 默认通过 `orchestrator.background` 运行：由 Windows WMI 服务创建独立宿主，再启动主控。它不属于启动它的终端或聊天会话的进程树，关闭终端、编辑或回退聊天都不会结束试玩进程（这正是 [INCIDENT_20261024.md](INCIDENT_20261024.md) 里那次中断的修复）。不需要管理员权限，不创建定时任务。HUD 的暂停和继续照常通过控制通道工作；试玩结束后宿主随主控退出，不自动重启，也不进入额外章节。

续跑用 `.\start_gpt.ps1 -Play -Resume runs\gpt-native\<运行目录>`，模型、知识范围、推理强度和剩余章节沿用原运行。后台启动与退出状态、PID、退出码和输出日志在 `local\background\<启动时间>\`（`status.json`、`output.log`）。单实例互斥量与工具端口检查避免重复接管游戏桥接。准备、聊天、HUD 服务与 HUD 窗口也可以由同一种宿主启动。

验证：`python -m unittest calibration.background_test` 结束启动命令的进程后，确认独立宿主及其子进程仍在运行，随后正常结束并记录退出码。

### 通关后唤起聊天与切换会话

原生 GPT 试玩结束后，HUD 的暂停 / 继续按钮变为"唤起 agent"。点击后由独立后台宿主启动 `orchestrator.chat`，接续原会话历史，在同一个 HUD 输入框收发消息；空闲时只等待，不主动发起模型轮次。聊天模式不建立游戏桥接、工具端口或录制连接，游戏动作、观察、Bash 规划和继续试玩都被拒绝；HUD 显示"试玩已结束 · 可聊天"，不会把唤起当作进入下一章。重复点击由宿主互斥量与唤起状态防重。如果同一个 Codex 线程正被 Codex 桌面端占用（报 `already has an active writer`），主控复制历史另起线程继续。

输入框上方的会话下拉框列出运行记录中未归档的原生会话，以运行时间、模型和短 ID 区分。只在本次试玩已完成、智能体没有正在回复时可以切换：后台通过控制通道正常释放旧聊天宿主，等它退出后启动目标会话，收到目标的新心跳才更新 `hud_session.json`，HUD 窗口不用重启。历史消息、发送目标、模型遥测和该会话的 Fast 偏好一并切换。各会话之后的聊天记录保存在已完成运行目录的 `chats/` 下，旧会话没投递的指令不会重放；HUD 的游戏成绩仍取已完成试玩的数据。新一局试玩仍默认跟随新的 `runs/latest.txt`。

验证：`calibration.conversations_test` 覆盖归档过滤、重复身份、目录越界拒绝、消息和偏好隔离、游戏成绩保留、启动失败回退和活动游戏拒绝交接；`calibration.agent_control_test` 覆盖聊天模式的门禁。实测：唤起后收到公开回复，游戏动作计数保持不变；切换到历史会话收到回复，再切回原会话成功。

## 执行器公共接口（2026-10-25）

HUD 读取当前运行的 `metrics.json`、`control.sqlite3` 和 `public_events.jsonl`，不读取任何聊天客户端自己的日志。模型与推理强度由执行器确认；取不到的字段保持未知。公开事件只包含消息、动作说明和压缩状态，不导出内部推理。

- `orchestrator/session_controls.py`：公共消息队列、暂停 / 继续、停止、目标更新 / 清除、剧情模式、推理强度偏好和心跳。执行器声明 `RuntimeCapabilities`，实现推理强度校验与协议中断；支持在活动轮次追加输入时再实现 steer。
- Codex 用 `turn/steer` 追加提示；Claude Code 没有这个能力，通过官方 stream-json 的 interrupt 控制请求结束当前轮，下一轮只提交一次待投递消息（参考 anthropics/claude-agent-sdk-python 的 `_internal/query.py`）。两个执行器都等已经开始的游戏工具结束后才确认暂停。
- Fast 是 Codex 的能力，Claude Code 不显示这个开关，也拒绝相应的控制请求。推理强度选项来自当前执行器的能力或模型目录，后端再次校验。
- `orchestrator/modes.py` 与 `orchestrator/prompting.py`：游玩模式、按模式注册的游戏工具、剧情规则、恢复提示与限额模拟说明。Claude 执行器也可以显式使用 `--mode explore --sim-assist`；限额辅助必须在容器运行方式下使用。
- `simulate` 是公共 MCP 工具（Codex 里叫 `celeste_simulate`），与 observe / act / cutscene / exit_level 使用相同的阶段与暂停门禁；体力、预测上限和退款规则不因执行器而变。省略 `candidates` 只查询体力。
- `orchestrator/telemetry.py`：写入两种执行器共用的公开事件；HUD 用同一个气泡历史显示消息和压缩状态。旧录像目录没有公开事件文件时，仍可读取原来的 Codex 公开事件，只用于已有录像的历史。

HUD 的新建、准备、取玩家名、切换、断开、重新唤醒和开始试玩，都经 `orchestrator/runtimes.py` 的执行器接口调度，支持 Codex 与 Claude Code（包括经 Claude Code 使用的 Anthropic 兼容提供方）。后台的准备（`orchestrator.preparation`）与聊天（`orchestrator.chat`）是通用入口；`orchestrator/lifecycle.py` 按执行器是否需要 MCP，托管不建立游戏连接的准备与聊天环境。

会话管理里先选"执行器与提供方"，再选模型和推理强度，点"新建并准备"。Codex 的模型来自它公开的模型目录（经 HUD 服务的 `/api/models` 读取 app-server 的 `model/list`，按隐藏标记与输入模态过滤，缓存 5 分钟，可手动刷新；读取不创建线程，也不读取或复制登录凭据；目录可能是服务端缓存或内置清单，实际能否访问仍以推理请求为准）。Claude Code 的模型来自 `configs/providers.json` 与本机 `configs/local.providers.json` 的 `models`，界面会标明来源，不冒充在线发现。部署向导填写的新模型会加入提供方配置，并要求声明该模型实际支持的推理档位。`models` 每项支持 `id`、`label`、`efforts`、`default_effort`；自定义平台没配置列表时报错，不拿其他执行器的列表兜底。认证或模型校验失败不会先断开当前会话。

推理档位没有全局固定名单：Codex 完整保留模型目录返回的 `supportedReasoningEfforts`，其他提供方完整保留模型配置的 `efforts`。创建会话、手动切换和智能体的 `set_effort` 都按当前模型的能力校验；HUD 的文字与档位条随这个列表显示。能力列表缺失时不猜测档位；配置声明也不能绕过底层执行器的实际支持，切换仍要执行器确认后才记为生效。

聊天与取名沿用原会话 ID、工作区及模型选择；HUD 展示服务回报的实际模型名。会话列表的身份由执行器、提供方和会话 ID 共同决定，避免不同执行器的 ID 相同导致历史混用。旧格式的 Codex 准备证明仍能识别，同样要通过摘要与工具校验。

通用命令行示例（准备和聊天不连接游戏、不开始录制）：

```powershell
.\.venv\Scripts\python.exe -m orchestrator.preparation --engine claude --provider anthropic --agent claude-live --model opus --effort high --knowledge explore
.\.venv\Scripts\python.exe -m orchestrator.chat --run runs\claude-live\<准备目录>
```

命令行准备完成后写入 ready 状态；HUD 管理的准备由后台监控建立并接入这个状态。开始试玩用 `--prepared`，并显式选择存档与章节范围。`start_gpt.ps1` 是 Codex 的快捷入口，内部调用同一套模块。

增加其他执行器时，在 `RUNTIMES` 里注册适配器，提供配置、凭据、模型目录与选择校验、runner 工厂和提供方列表；通过 mcp、fast、默认模型 / 强度 / 知识范围等能力配置接入公共生命周期，不需要为 HUD 或后台宿主再复制一套流程。

已经移除的旧路径：`--codex-thread` 与聊天日志读取器、内置的 openai 转换网关预设及其专用部署向导步骤、Bash 里专用的 game exit / game story / simulate 拦截和旧的菜单命名回退。自定义 Anthropic 兼容平台与域名 / 宿主端口限制仍保留。桥接最低要求 0.12.4，启动前只读检查，不满足时不会录制也不会选择存档；桥接 0.12.5 移除了 `name_new_save`，新建存档只用 `create_save`。

验证：`calibration/runtime_controls_test.py`、`agent_control_test.py`、`sim_assist_test.py`、`connectivity_test.py`、`session_bootstrap_test.py`、`play_scope_test.py`、`lifecycle_test.py` 与全量 calibration 回归，都不启动付费模型、不推进真实游戏。生命周期联调用真实 stdio 子进程代替模型服务，覆盖 Claude 准备的阅读证明、聊天、断开、再唤醒、取名，以及模型和会话 ID 的延续。

## 网页 HUD

### 桌面窗口与 OBS 浏览器源

OBS 里的 HUD 是独立的浏览器源，地址带 `?surface=obs`，卡片直接填满来源的内容区域，不读取桌面窗口的坐标或宽高。默认来源 420×760，放在画布 (1480, 40)，不锁定，可以在 OBS 里单独移动、缩放：改来源属性的宽高会调整内容区域，字号保持不变；OBS 的变换缩放则像其他来源一样整体缩放。桌面窗口的缩放手柄和聊天控制区不会出现在 OBS 里。`tools/obs_setup.py` 只迁移旧版铺满整个画布的 HUD 来源，之后保留你在 OBS 里自定义的位置、缩放和来源尺寸。

桌面 HUD 是独立的无边框窗口，不跟随游戏的位置、大小或可见性；游戏最小化、关闭或未启动时也不会自动隐藏。拖动顶部移动、拖动边缘调整大小，气泡区可以直接滚动。顶部有"置顶"、最小化和关闭按钮，置顶选择会保存。窗口不在任务栏显示，双击托盘图标或托盘菜单"显示 HUD"恢复；托盘菜单还有最小化、置顶、恢复默认位置和大小、"退出 HUD"。关闭按钮和 Alt+F4 只隐藏窗口、保留托盘图标；只有"退出 HUD"结束桌面前端，而且不会停止智能体、HUD 服务或 OBS。

正常窗口的位置、宽高与置顶选择自动保存到 `configs/local.hud-window.json`（最小化时的坐标不覆盖正常位置）；旧的按比例配置只做一次迁移，不再查询游戏窗口。Ctrl + 滚轮调整字号，每档 5%，范围 60%～180%，保存在 `configs/local.hud-font.json` 并同步到 OBS。窗口最小高度 260 像素，默认 760 像素；所有可滚动区域（消息历史、底部控制区、展开的目标和输入框）统一用细滚动条。窗口用 `WS_EX_TOOLWINDOW` 样式隐藏任务栏条目，样式在页面加载完成后应用，避免重建窗口打断 WebView2。

桌面窗口和 OBS 浏览器源可能保留旧页面。页面会在 `configs/hud.json` 的 `page_version` 变化时自动重新加载，不必重启游戏或智能体。页面遇到暂时缺失的 `metrics` 时保留上次画面；静态文字只在内容变化时更新，公开消息按 ID 增量更新。

验证：`calibration.hud_window_test` 覆盖窗口不自动显隐或重复移动、最小化 / 恢复 / 关闭 / 置顶由用户控制、最小化时不覆盖正常布局，以及页面命令门禁；布局测试覆盖独立坐标、置顶持久化与屏幕边界恢复。

### 解说历史

解说区以聊天气泡显示本次运行最近 12 条完整的公开解说和动作说明，来自 `public_events.jsonl`（旧录像目录是 `codex_events.jsonl` 里已完成的 agentMessage）与 `decisions.jsonl` 的 thought，不读取内部推理。日志增量读取，长句不省略。新消息出现时自动滚到底部；手动上翻时保留阅读位置，回到底部后恢复跟随。气泡区自动填满窗口剩余高度。上下文压缩以一条"系统"气泡显示：开始时提示"正在压缩上下文"，完成后更新为"上下文压缩完成"，不展示压缩摘要。

HUD 服务提供同源的 `/hud/history`。这个只读显示层不占用游戏桥接连接，不影响章节范围与录制。

### 聊天、暂停与继续

聊天输入框、发送和暂停 / 继续按钮在 HUD 底部，不另开聊天窗口；Enter 发送，Shift+Enter 换行，中文输入法选词不会误发。输入控件只在桌面窗口与预览中显示，OBS 里只显示公开内容。你发的提示和智能体的公开回复都出现在气泡历史里。

消息进入当前会话：运行中的 Codex 轮次用 `turn/steer` 追加；空闲时作为下一轮输入，暂时不能追加就保留待投递。状态"已提交"只表示接口已接受，不等于模型已经读到。当前轮次和线程 ID 都由主控核对。跨进程队列用每次运行的 `control.sqlite3`，控制请求会核对当前运行目录与本机来源。

暂停时先关闭游戏操作入口，中断当前模型轮次，等正在执行的游戏动作结束，再确认"已暂停"。暂停期间仍可以发提示、收回复，`act`、`observe` 和规划用的 Bash 被门禁拒绝；只有"继续"恢复操作。暂停时间不计入现实时间预算，也不记作额度等待。新启动可以用 `--start-paused` 先聊天再继续；续跑沿用原会话、存档和剩余章节。

底部主按钮按完整的生命周期统一决定文字、禁用状态和点击动作：准备中 / 接入中 / 启动中不能唤起；试玩中显示暂停，暂停后显示继续，过渡时显示暂停中 / 恢复中；只有已结束且断开的会话显示"唤起 agent"，已准备但断开的会话显示"连接 agent"；连接失败显示"未连接"。聊天待命和通关后已连接的聊天不提供游戏暂停。

验证：`calibration/agent_control_test.py` 覆盖进行中动作的暂停、暂停期间的消息投递、继续后计时、错误运行与跨站请求拒绝；`hud_history_test.py` 覆盖压缩状态和隐私过滤；`calibration.hud_controls_test` 执行页面里实际的状态函数，覆盖各阶段与操作的组合。

### 会话管理

HUD 底部"会话管理"提供新建并准备、断开会话、章节选择、存档选择和开始试玩。新建时可以填写名称，选择执行器与提供方、模型及推理强度，并保留当前的 Fast 偏好；后台生成独立的智能体标签和 Docker 工作区，按所选知识范围真实读完必读资料，不继承旧聊天或旧笔记。准备由独立后台宿主执行，HUD 显示状态；完成后自动接入一个只聊天的待命会话，旧会话保留在下拉框里可以切回。准备或接入失败时保留原来的选择，并尝试恢复原聊天；创建前会再校验一次所选模型与强度，失败发生在释放旧聊天之前。

"开始试玩"是单独的操作，只对新准备的会话开放：核对阅读证明、交还旧聊天宿主后进入所选章节，先保持暂停，点"继续"才交给智能体操作。"断开会话"只停止空闲的聊天后台，历史、下拉条目和准备证明都保留，可以用"连接 agent"或"唤起 agent"重连。试玩中要先用"立即停止并保存"结束，才能管理会话；正在回复或准备 / 接入时禁用冲突的操作。展开页面或新建准备都不会自动启动聊天或真实游戏。

启动范围可以选"从指定章继续"（按官方章节顺序，`--scope campaign`）或"仅当前章节"（`--scope chapter`），范围与动态停止目标分开保存：没有设置停止目标时一直玩到所选范围结束，清除目标不会修改范围。探索模式的限额模拟是可选项，缺少预置模拟器时不影响普通试玩。会话切换同时继承存档名与槽位。没有任何历史运行时，HUD 进入真正的空闲状态。

后台操作写入当前运行的 `session_operation.json`，同时在 `local/hud-session-operation.json` 保留启动中的指针，所以 `runs/latest.txt` 已经指向新的运行目录、但主控还没连接时，HUD 仍显示"正在启动"。HUD 服务重启后可以根据独立宿主的状态恢复监控。待命状态用 `session_kind=ready` 与真实的 `prepare_summary.json` 区别于已通关的运行，不伪造通关记录。固定显示某次历史运行的 HUD 服务（`overlay.server --run`）不开放管理功能。

### 推理强度与 Fast

底部有"当前会话推理强度"下拉框，与新建会话的强度设置分开。选具体档位会手动固定，智能体不能再用 `set_effort` 改回；选"推理：自动"撤回固定、恢复由智能体自行调整。选项按当前模型的能力生成，后台再次校验；旧版主控没有 `effort_control` 能力时禁用。偏好按会话写进 SQLite，切换、唤起和续跑都保留；准备后开始试玩也继承这个设置。

切换时不主动打断当前轮次，也不等待或取消动作锁；如果正有 Codex 轮次在进行，用 steer 通道请求它在当前工具结束后自然结束，主控再按新档位继续。只有 `turn/start` 成功返回后才更新 `metrics.effort`，等待期间用 `effort_pending` 显示"下轮生效"。空闲聊天里修改不会发起额外的模型请求。

`Fast：开 / 关`（只有 Codex 有）控制服务档位：下一轮 `turn/start` 显式传 `serviceTierForTurn=priority/default`，不打断当前回复；回复中切换会显示"下轮"。设置存进当前运行的 SQLite 偏好，唤起聊天时保留。

实测（Codex）：经 HUD 接口把推理强度从 high 改为 low 并等待下一轮生效，再恢复"自动"撤回请求，原会话、Fast 关闭状态和游戏都保持不变。

### 目标与停止条件

"目标与停止条件"展开区提供自由文字任务、可增删的停止条件、"任一 / 全部"组合、更新和清除，以及单独的"立即停止并保存"。文字任务通过控制通道交给智能体，不把自然语言的"已完成"当作自动停止的依据；结构化条件由主控核验。

条件引擎支持房间、地图、面别、当前地图完成状态、本地图死亡次数、游戏帧号和运行时间，提供相等、变化、阈值及相对增量运算；HUD 按字段提供适用的选项。房间和当前地图完成条件绑定设置时的地图 SID 与面别，死亡导致的房间变化不算通过。更新会重新绑定当前状态；清除撤回自定义任务及条件，启动时的地图范围仍是本次试玩的边界。纯文字目标没有额外的自动停止条件。

停止触发后，主控拒绝新动作，通过桥接连接的 progress / cancel 协议中止当前动作，等动作锁释放再保存录像。换图菜单也会检查停止请求；当前地图完成后停止会清空后续自动换图的队列。原生 GPT 试玩结束后始终通过自己的桥接连接 deactivate 解除接管，恢复游戏运行和正常输入（通关、用户停止、预算用完和异常退出都是如此）；正常路径先保存录像再恢复游戏，初始化或其他收尾异常也由外层 finally 交还控制，`summary.json` 的 `game_released` 记录是否交还成功。暂停 / 继续只暂停试玩，不走结束流程，也不结束当前录像。交还控制后游戏可能继续变化，续跑会重新核对当前观测，不能假定游戏还停在上次的那一帧。

目标记在运行目录的 `goal.json`；仍有效且没有触发的目标会随 `--resume` 延续。已经开始停止保存后，清除不能撤回这次终止。通关后的聊天阶段目标控件禁用，下一次正式试玩才启用；保存目标不会启动下一章。

验证：`calibration.goals_test` 覆盖文字目标的更新 / 清除、条件组合、相对阈值、死亡排除、A / B 面隔离、单连接取消与后续回复配对、防止额外动作、自动换图截断，以及等待进行中的动作再结束。实测（2026-10-24，test 存档序章）：设置、更新、清除、完成地图条件触发和停止保存都已验证；其他条件与进行中取消以回归测试覆盖为主。

### 存档选择与新建

"会话管理"里有只读的存档列表与"新建独立存档"入口，初始为空，不默认选择 test，也不默认新建。每次切换运行都清空选择；开始试玩的请求必须包含明确的存档名及 `create_save` 布尔值。准备资料和聊天阶段不选择也不创建游戏存档。存档名允许重复；已有存档的列表按槽位区分并提交 `save_slot`。现有存档名从部署配置（`configs/local.deploy.json`）里游戏目录的 `Saves` 只读获取，刷新页面与读取列表都不连接游戏桥接。

新建只在点"开始试玩"时执行，只能从序章开始；允许与已有存档同名，始终放在现有最新存档的下一个槽位（不填中间的空位，那些编号可能属于玩家自己的存档），不会改成进入或覆盖旧档。启动后实际的存档名和槽位写进本次运行的 `run_state.json`，续跑与换章沿用槽位；连接游戏时也检查槽位，避免进入同名的其他存档。

名字输入框可以留空：点"开始试玩"后显示"取名中"，由同一个已准备的会话做一次只聊天的命名，再用结果创建存档并进入序章。填了名字就直接用，不发起命名轮次。不规定名称的语言、风格、前缀或唯一性，只校验游戏输入框能显示的字符与 20 个字符的上限。命名时先释放原聊天的写入者，由独立后台宿主恢复同一个线程，只聊天、不连游戏；最终的公开回复就是名称，显示在 HUD 历史里。每次请求有独立 ID，结果原子写入 `save_name_result.json`，只接收与本次 ID 匹配的成功结果；空名、超长、失败、被中断或超时都不会启动游戏，也不会用固定或随机的默认名代替。命名成功后重新读取实际的线程身份，交给普通的试玩启动流程；进入序章后仍先暂停，等你点继续。命名提示说明这是"玩家角色名"：同时作为存档显示名，并用于游戏角色在对话里的称呼；不会给已有存档改名。会话显示名与游戏存档名相互独立。

命令行对应 `--save <名称> --chapter 0 --create-save`；已有存档用 `--save <名称> --save-slot <槽位>` 指定。不加 `--create-save` 时只进入已有存档。

验证：覆盖目录清单过滤、同名新建、同名槽位选择、明确选择、新档的章节范围、手工名字、空名触发命名、过期或无效结果阻止启动、命名中的按钮状态、槽位变化中止与主控参数传递。实测（2026-10-24，Codex）：完整走通 HUD 新建会话 → 准备 → 新建存档且名字留空 → 会话自动取名 → 桥接原生创建 → 进入序章；新存档放在新的槽位，进入后保持暂停、没有执行游玩动作，停止保存 265 帧录像（约 4.42 秒）后经暂停菜单保存退出到地图；已有主存档的哈希都没有变化。单独的命名测试里会话给出的名字是"踏雪微光"（只用于测试，不是默认名）。

## 游戏侧接口

### 新建存档（桥接 0.12.2 起）

`{"cmd":"create_save","name":"…"}` 在接管中的稳定选档页执行，调用游戏的 `OuiFileSelectSlot.OnNewGameSelected()`，正常初始化新存档并开始进入序章。它只供主控使用，不作为游玩工具开放给智能体，而且要由你显式选择新建。名称允许重复，槽位自动选择（桥接 0.12.6 起放在现有最新存档的下一个槽位），不会覆盖已有的主存档或残留的 Mod 存档；保存、创建或游戏动作进行中时拒绝重复创建。旧版桥接通过 `hello.create_save` 能力协商保留菜单兼容路径。

返回 `slot`、`name`、`started`、`persisted`。`started` 表示原生的创建 / 入场流程已经开始，不等于已经写盘；写盘仍由游戏原生流程处理。`dry_run: true` 只检查并返回候选槽位，不改变选档状态、不开始游戏、不创建文件。实际创建后主控等待入场，并按返回的槽位核对身份。这个动作暂时只支持官方《蔚蓝》地图。

实测（2026-10-24）：用已有的名字 test 做 `dry_run` 预检，返回新的槽位、`started=false`、`persisted=false`，光标与卡片状态不变，已有主存档的哈希不变，结束后交还游戏控制。测试覆盖新动作只调用一次、转场等待不重复、出错不回退成另一次创建、旧版菜单兼容。

### 剧情模式与分支对话（桥接 0.12.3 起）

HUD 底部的"剧情"下拉框提供"自动跳过"和"agent决定"，开始前或游玩中都可以切换，随当前会话保存、续跑时沿用；默认自动跳过（命令行 `--cutscene-mode auto/agent`）。自动模式用原生暂停菜单跳过剧情，跳不过时推进普通对白；agent 模式把开场和关卡内的剧情交给会话，由它自己等待观看、推进、选择或跳过。加载、转场、死亡与重生仍由主控按正常速度处理。只有开放了 cutscene 工具（探索模式、直播模式或 `--cutscene-mode agent`）时，HUD 才能切到"agent决定"。

`cutscene(action, frames=30, choice=None)`（Codex 里叫 `celeste_cutscene`）支持 wait、advance、choose、skip。第六章营火对白的选项独立于普通文本框，桥接只公开当前可见选项的文字、索引、选中位置和可操作状态。advance 遇到选项时拒绝确认；choose 必须明确指定当前选项的索引，逐步移动并复核后才确认；选项还在动画中或内容发生变化时停止，不默认选第一项。wait 的 frames 上限 180，较长的收尾动画要分段等待。

交互式剧情里仍可以用 act 发送真实的方向、跳跃与冲刺输入，不能把所有 inCutscene 状态都当成只能观看或翻页。例如序章的乌鸦教学在 Dummy 状态等待方向与冲刺，之后才切换为 BirdDashTutorial，不能靠这个玩家状态提前放行。真正有分支选项时禁止用普通 act 移动选项，必须用 choose。

实测（2026-10-25，Codex，测试用的新存档，序章）：老婆婆的对白由智能体推进 12 次后恢复操作；乌鸦教学一开始发现普通 act 被剧情标志误拦截，修正后同一会话从当前位置恢复，真实的方向与冲刺输入成功，分段 wait 播放结尾，完成序章后保存到选章地图，没有进入第一章。结束时确认桥接已交还游戏，没有新增主存档，其他存档的哈希不变。第六章的选项尚未实际试玩，分支部分目前用模拟观测与真实游戏的类型字段检查。

### 当前可见的剧情文字（桥接 0.12.4 起）

每次观测的 `story` 返回当前显示的对白文字、页码、等待确认状态及 `speakerPortrait`（当前头像资源标识与表情，不编造角色姓名）。覆盖序章开场、明信片、结尾字幕和可见的乌鸦教学提示 / 按键。读取的是 FancyText 当前页里字符实际显现到哪里；不返回下一页、隐藏字符、完整脚本或未来的分支。普通对白的部分显示会随 wait 逐渐补全；等待标志只用于判断输入时机，不能代替理解文字。

剧情工具返回文字和图片，使用同一种响应转换。截图依旧是 320×180 的游戏画面层，不含对话框等界面层；`story` 与 `dialogChoices` 负责提供这些界面文字，提示词已写明要读取它们。

实测（2026-10-25，Codex，测试用的新存档，序章）：智能体实际复述了"夫人，请问一下。"及下一页"前面的牌子损坏了...这是山路吗？"，读到 MADELINE / normal 的头像标识，并自行保存退出；没有新增主存档，结束后已交还游戏。

### 退出关卡（直播模式）

`exit_level(reason)`（Codex 里叫 `celeste_exit_level`）只在直播模式下注册，只在用户（直播的操作者或观众）明确要求退出时调用：复用主控当前的桥接连接，通过游戏暂停菜单保存退出到地图 / 主菜单，结束本次运行并收尾录像；不算通关，也不会自动进入下一章。暂停、只聊天、准备和停止阶段禁止调用。持久化工具列表里缺少它的旧线程需要新建准备会话。

实测（2026-10-24，Codex，测试用的新存档）：新会话自己调用 `celeste_exit_level` 成功，结束原因"agent 退出关卡"，`completed=false`，最后停在地图；没有游玩移动动作，没有新增主存档，其他主存档哈希不变；录像 430 帧约 7.17 秒，无缺帧无重复，结束后恢复正常游戏运行。

### 通关、片尾与交还控制

原生的地图 completed 事件可能早于片尾对白和结算页。`map_complete` 停止条件要等当前剧情结束；恢复到已通关但还在片尾的关卡时，重新建立待结算状态。通关后的普通目标停止仍走章节结算路径，清空下一章队列；"立即停止"保持立即生效。出现 AreaComplete 后，先发送 120 帧中立等待展示结算，再确认返回选章地图；只在结算场景按确认，地图加载过程中只等待，停在稳定的选章菜单，不进入下一章。剧情的 wait / advance 本身不再设置 complete 截断条件，避免通关后每次等待只执行一帧。序章正常返回地图不再被误报为收尾异常；`summary.json` 额外记录 `end_scene` 与 `finish_error`，不隐藏真实的收尾错误。

录制停止分成"停止采集"与"文件后处理"两步：确认锁步已关闭、插件不再录制后，先通过原有的会话连接 deactivate 交还游戏，原始文件的封装与纯享版转码随后继续，不再阻塞游戏控制。外层 finally 仍负责关闭连接与异常兜底。回归覆盖片尾期间不触发 `map_complete`、恢复片尾、立即停止、结算停留以及"先交还、后转码"的顺序。

实测（2026-10-25，Codex，测试用存档，1A）：复用原会话补完 1A 片尾，随后用同一个收尾函数确认 AreaComplete，退回稳定的选章页（地图标记在 2A，没有进入 2A），解除接管。逐段检查录像：篝火片尾、章节完成画面与确认后的过渡都完整保留。

## 探索模式

### 观测中的收集品与地形

之前收集品混在普通实体列表里，压缩实体时会去掉不运动实体的反射字段，因而丢掉草莓的收集、幽灵和翅膀状态；探索提示词也只强调完成章节。现在单列当前观测范围内的收集品，保留相关状态，并提示先观察、短尝试，放弃时说明原因；不要求全收集，不提供隐藏位置。

`exits` 只是相邻房间与当前边界的投影，没有验证开口或从当前位置是否可达；之前"离开范围就进入相邻房间"的说法过强，已更正。字符地图的图例原本保存在桥接数据里却没有发给智能体，现在随地图一起发送。

新增静态空区分隔提示：只在已有的整房间字符地图内，对非 `#` 格子做连通分组，用角色碰撞箱的中心定位，提示弹簧、水晶、收集品是否在另一个空区里。它不搜索动作、不模拟物理；同一个空区不代表能跳到，危险与动态物体仍要实际观察判断。例如房间 11 的一份归档观测分出两个空区：初始位置与草莓在同一侧，弹簧在另一侧。

这些观测内容（静态地形检查与收集品清单）只给探索模式，速通模式不替智能体做路线分析。

验证：`python -m unittest calibration.observation_context_test`，以及用房间 11 的实际归档观测检查格式化输出。

### 探索模式的模拟体力

探索模式在本机有预置模拟器时默认开启可选的限额模拟（`--sim-assist`），HUD 也可以显式选择是否启用，与速通模式的 `--sim` 分开。智能体容器仍然没有 `/sim`、完整场景快照或速通知识库：主控在原连接上取得当前帧快照，由一个独立的、无网络、只读、限制内存与 CPU 的 Docker worker 执行有界预测。入口是公共 MCP 工具 `simulate`（Codex 里叫 `celeste_simulate`），参数为 `{"candidates":[["60,R"]]}`，省略 `candidates` 免费查询余额。旧线程缺少这个工具时不能开启。准备、聊天、暂停、停止阶段都不能预测。

规则：体力上限 100、初始 40；真实操作中每 60 个移动帧恢复 1 点，每分钟最多恢复 20 点；首次进入新房间奖励 15 点（起始房间不奖励，回到去过的房间不重复奖励）。等待、自动剧情、死亡不恢复体力。每次花费 `8 + ceil(总预测帧数 / 12) + 4 × 额外候选数`：单条 60 帧花 13 点，三条各 120 帧花 46 点。每批最多 6 条，每条最多 180 帧、合计最多 600 帧；按提交量收费，模拟中提前死亡不降价。后台或快照获取失败时退款；正常返回的死亡 / 不支持结果照常收费。

钱包在运行目录的 `sim_energy.json`，由主控加锁、预扣、原子保存；`--resume` 继承余额与首次到访记录，不因重启补满；新开一局重新获得初始体力。`--sim-assist` / `--no-sim-assist` 可以显式控制；旧运行续跑沿用原设置。速通模式的 `--sim` 与限额辅助不能同时开。

HUD 把模拟体力显示为"推演额度"（余额 / 上限），网页 HUD 悬停可以查看规则；关掉限额预测时，HUD 不显示推演额度、模拟器调用、推演路径、推演最速这几栏。预测轨迹沿用规划回放；普通返回只提供每条路线的结局、末帧和事件，完整轨迹按需读取 `/workspace/game/sim_assist/latest.json`，避免每次把几百帧的数据灌进上下文。入门资料改动后，之前准备目录里的知识库摘要会失效，新开一局前要重新完成准备。

验证覆盖计费与边界、退款与余额持久化、并发防超支、恢复限速、房间奖励去重、worker 隔离、原生命令拦截与暂停门禁、回放格式读取；还用一份已有的场景快照实际执行了两条模拟路线（没有连接或推进真实游戏）。新开一局的实际试玩、赚取 / 花费体力与录像的联动仍待实局验收。

### 提示词与知识库

独立的智能体应通过 `compose_prompt()` / `play_prompt()` 接收完整的系统提示词，并保留 `KbStudy` 准备阶段（不传 `--no-study`）。需要完整阅读的清单由 `required_files()` 生成，速通模式包含规则、社区资料和模拟器说明；只显示索引或让程序扫描文件不等于完成阅读。用 `--no-agent` 加 `tools/game_tool.py` 手动调用游戏工具时没有 Claude Code 的 Read 结果流，按行核对的准备阶段用不上，这样的运行不能标记为"已读知识库"。

直播节奏只用于探索 + 直播（`explore_live_zh.md`）：每次决策争取在约 10～20 秒内提交短动作，但不要求为了省时盲按；尽量每 5～10 秒说明有意义的进展，没有新发现时不编造。探索模式的提示词另外要求单次规划程序最多 15 秒（可调参数 `explore_program_s`，主控按同一个值强制结束超时的程序；`explore_program_runs` 可以再限制两次 act 之间的次数），长程序用 `show.status()` 报告真实进度。10 秒提醒只是后备，系统不能在模型还没有输出时替它生成解说。速通 + 直播只加 `live_zh.md`（解说计时 10 秒、可按要求退出关卡），不改变"以最短章节计时通关、想多久由智能体决定"的目标。

## 录像专用的独立游戏声音

`configs/recording.json` 的 `audio_source: "game_nrt"`（默认）启用桥接里的独立 FMOD Studio 系统（桥接 0.12.0 起；两条音轨 0.12.7 起）。它读取本机安装的官方音频 bank，使用 `NOSOUND_NRT`，不打开声卡、不接系统扬声器，也不需要虚拟声卡驱动。游戏进程原本的声音继续由 OBS 用于直播；`continuous_music: true` 时，智能体思考和规划回放期间直播的 BGM 继续播放。

独立系统镜像游戏声音事件的开始、停止、释放、cue、显式定位，以及每个游戏帧的参数、音量、音高、空间属性、总线与 VCA 状态。为了让完整版与纯享版的音乐都连贯，桥接开两个这样的系统，分别生成两条音轨：完整版音轨每个成片帧都同步混音一次（800 个 48 kHz 立体声采样），规划回放帧照抄游戏此刻的总线状态，只放音乐、音效暂停；纯享版音轨只在真实游戏帧混音。思考和暂停期间两条都不推进。（0.12.7 之前只有一条音轨，回放帧写入静音。）录像在中途开始时，以当时正在播放的事件与音乐位置为起点，之后不跟随直播音乐的位置。

桥接通过本机共享内存 `Local\CelesteAIRecordAudio-47776` 发布 PCM，按 OBS 时钟令牌配对，而不是按墙钟时间裁切。OBS 锁步插件把对应的音频写进 `audio.wav`（完整版音轨，合进 `gameplay.mkv`）与 `audio_play.wav`（纯享版音轨，只写真实游玩帧，纯享版 `gameplay_pure.mkv` 直接用它）。这个模式忽略 OBS 的混音输入，所以锁步成片包含游戏的 BGM、音效和环境声，不包含麦克风或桌面声音；普通的 OBS 推流 / 录像仍使用你原有的音频配置。录像音频不是可监听的 OBS 场景源，不会经 OBS 监听意外多出一份声音。

两端通过 `hello.record_audio_nrt`、`hello.record_audio_tracks` 和 `clock.plugin.audio_nrt`、`clock.plugin.audio_tracks` 协商能力（音轨数都是 2），旧版本明确拒绝启动这个模式。共享内存（第 2 版）包含版本、采样格式、音轨数、每个槽的令牌、错误标志及回放标志（插件与章节计时 -1 互相核对）；缺失、被覆盖、格式不符或混音失败时录像报错，不回退到直播声音。音频帧数严格对应实际保留的视频帧，不使用旧的声音偏移、静音起点检测或接缝淡入淡出；回放帧跟不上节拍时也不补帧（补帧只能重复同一块声音）。`audio_source: "obs_mix"` 保留原来的混音裁切方式，原有的声音延迟校准脚本固定使用这个旧模式。

更新桥接和 OBS 插件后要重启两者。这个实现针对 Windows、60 fps 与官方 bank；不把外部音频资源复制进仓库，也不保证其他 Mod 的自定义 bank 可用。结束或取消试玩时仍先结束录像，再解除游戏接管、恢复正常运行。

验证：`python -m unittest calibration.recording_audio_test`；原生离线混音测试不需要运行游戏、不改动存档：`dotnet run --project calibration/audio_mixer -p:CelestePrefix="<Celeste 安装目录>" -- "<Celeste 安装目录>"`。覆盖两条音轨的实际 PCM 不是静音、直播与录像各自的进度、规划回放时完整版音轨继续放音乐且音效总线暂停而纯享版不推进、没有新混音块时写静音、一次性音效、音量与停止同步、环形槽覆盖检测。录完的 `audio.wav` 可以用 `python tools/check_recording_audio.py` 离线检查断口。

实测（2026-10-24，单音轨版本）：同一段菜单画面推进 120 帧、等待 2 秒、再推进 120 帧。等待期间直播音乐从 47722 ms 走到 49749 ms，录像音乐保持在 47333 ms，混音帧数保持 120；成片 240 帧，PCM 每声道 192000 个采样（48 kHz），缺帧和重复都是 0；AAC / MKV 时长 4.021 秒（含编码器封装延迟），原始音频严格 4.000 秒。结束后确认桥接未接管、锁步关闭、独立混音已释放，游戏恢复运行。

## OBS 统计面板显示 0.0 MB

专用 OBS 配置的标准录像目录是仓库里的 `runs/obs`。这个目录不存在时，OBS 33 的统计面板按标准输出路径查询磁盘空间会失败、显示 0.0 MB；锁步插件另外把录像写进每次运行的 `recording/`，所以录像本身不受影响。`tools/obs_setup.py` 的 setup 现在会自动创建这个目录；没有改动 OBS 的推流、音轨和编码设置。

## 原生 GPT 的完整流程实测

实测（2026-10-24，gpt-6.1-sol / high，Fast 关闭，test 存档序章）：经 HUD 的同源控制接口新建会话，真实读完入门资料后接入；验证了消息与回复、断开与唤起、启动时暂停，再试玩序章。目标的设置、更新、清除及重新设置都写进了实际运行的主控；暂停期间 `frames_played` 保持 131，恢复后继续同一段录像。序章的完成条件实际触发（`goal.reached=true`、`completed=true`、`user_stopped=true`）；41 次决策、死亡 1 次、章节计时 46.512 秒，最后的只读观测确认停在地图、没有进入 1A。结束后再次唤起同一个会话并收到聊天回复，HUD 仍连接、Fast 仍关闭。录像 55.004 秒、1920×1080 / 60 fps、H.264 / AAC，3299 个视频帧全部可解码，缺帧 0、重复 0，暂停没有把录像切成两段。

这次实测暴露并修正了：启动期间的状态提示丢失、准备会话的名称没有延续到试玩，以及序章正常返回地图被误报为收尾异常。修正后的收尾代码用真实的地图状态验证过，不推进任何游戏帧；普通章节仍要求出现预期的结算场景。

## 与速通正式运行的边界

- 直播节奏（`explore_live_zh.md`）只用于探索 + 直播；速通 + 直播只加 `live_zh.md`，不改变以最短章节计时通关的目标。解说提醒在直播模式下是 10 秒，其余半分钟，与执行器无关。
- `exit_level` 只在直播模式注册；`cutscene` 在探索模式、直播模式或 `--cutscene-mode agent` 时注册；`simulate` 只在开了 `--sim-assist` 时注册。没有剧情工具时，HUD 不提供"剧情交给智能体"的切换。
- 观测里的静态地形检查与收集品清单只给探索模式。
- Claude 执行器的运行没通关就停下（时间预算用完、出错、Ctrl+C）时游戏保持冻结（章节计时不走），用 `--resume` 续跑；通关、退出关卡、原生 GPT 会话与 `--no-agent` 照常交还控制。
- 新建存档放在现有最新存档的下一个槽位，不填中间的空位。
