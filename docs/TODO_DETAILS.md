# 待办设计与验收说明

本文补充 [TODO.md](../TODO.md) 中地图、路线和结构整理事项的背景、范围与验收要求。具体功能缺陷已经修复的部分仅作为设计背景，不重复列为未修问题。

## 全章地图与路线准备

### 提供完整章节地图，包含未访问房间

当前 `neighbors` 和模拟器的 `rooms` 只有房间名称、范围，详细观测只缓存已访问房间。补齐各房地形、实体定义与运动路径、危险物、出生点、检查点、触发器和候选出入口；提供章节索引与按房间查询，避免一次把全图塞进上下文。区分静态地图定义与当前实体状态，不以相邻范围冒充可通出口。

### 按入口区域表达房间连接

同一房间可能有互不连通的区域，只有房间名组成的邻接图不足以规划。记录候选连接的边界位置、进入区域、方向及机关条件，并用完整角色碰撞箱核验通路；静态连通和动态可达分别标注。

验收应覆盖从不同前房进入同一房间、却无法到达同一目标区域的情况。

### 增加正式速通前的路线准备与复用

先确定全章主路、分支与汇合点，以及关键机关、接触和出房位置／动量／资源目标，再执行房内动作。保存路线依据和待验证段，并随地图版本、章节面及目标变化校验失效；能力面向各执行器，地图读取不依赖开启模拟器。探索模式保留按访问范围提供信息的规则，不能默认泄露全图。

### 修正速通提示词的局部优化目标

当前强调把单房出门帧数优化到很难再快，容易忽略出房状态对后房的影响。改为服务于章节路线与后续入口条件，先概括关键机制如何产生连续房间的路线收益，再做局部模拟。以房9双重机关加速、带速进入9b直接横穿为验收案例，不能只比较房9的用时。

## 跨房验证与历史状态

### 扩展模拟器的跨房连续运行

当前止于开始换房，不能直接验证候选的连续衔接。需要模拟器核心源码／构建工程或协作者支持，正确执行转场及房间加载，保留或归一化玩家、输入、缓存和实体状态；不能通过手改速度、拼接单房结果冒充连续推演。静态全图查询与此能力分开提供。

### 自动留存关键位置的完整快照

当前首次入房缓存是观测，不是完整 `sim_state`，后者通常会被覆盖，复盘依赖智能体手动保存检查点。按运行保存入房、出房及必要检查点的完整状态、对应输入和版本来源，避免回访状态覆盖首次入房；明确原始快照与根据观测重建的近似状态。

验收应能恢复旧路线的起点，而无需猜补内部字段。

## 结构整理

### 梳理游戏编排与模块边界

对比审查发现 `GameSession` 的大函数和隐式状态交接增加了跨入口修改风险。明确其与导航、剧情／输入、录制、目标计量及执行器生命周期模块之间的状态、回调和失败契约；保留分段解析等纯规则边界，避免只搬动代码却继续共享一组可变标记。

验收以同一流程经过不同入口时行为一致为准，覆盖自动／智能体模式、续跑和异常收尾，不以文件数或函数长度作为完成标准。

### 统一导航目标的所有权与交接

当前 `piece`、`chapter_finished`、`chapter_queue` 分散表达当前段与待进入段，输入约束会受队列消费时机影响。后续建立明确的导航目标及开始、确认进入、取消／失败恢复契约，让菜单宏、智能体选关、续跑与输入核验使用同一目标。

验收覆盖自动与智能体模式、最后一章／多章、同章不同检查点、中途停止及失败重试；不要引入收尾代按或结算来源持久化。

### 统一增量预览的资源预算

读取器分配、待播合并、渲染队列各自限额，后续明确单条、整批、并发和临时副本的预算及背压契约，限制在分配前生效。保留完整记录跨公平窗口的进度与轮询公平性；

验收包括长短记录混合、持续写入、超过128个文件及慢消费者，既不无界增长也不静默漏画。

### 统一回放完成语义与覆盖记录

当前已用逐来源偏移修复收尾漏画，但读取位置、`previewed`、预览成功标记和最终记账仍分别维护。后续明确来源身份与搜索归属，区分已读取、已排队、已绘制、按房间过滤、因保护策略跳过及最终完成；不能由“发生过预览”或“统计完整”推断所有应显示路线都已处理。运行中预览、工具返回和 `drain` 使用同一套完成契约。

验收覆盖跨预算尾部、并行消息、文件移动／字节回退、失败后恢复、全批房间外路线和压力退化，验证有效路线覆盖、重复绘制与只记账一次。

### 明确异步收尾的资源所有权

当前已修复关闭超时提前删除工作线程日志的问题，但工作线程与 `close` 仍分别参与收尾。后续统一日志从写入、收集、交接到销毁的所有权，以及停止请求、线程实际退出、记账完成和清理完成的状态；等待超时不能视为线程已停止。

验收覆盖慢渲染、关闭超时、异常、重复关闭和新一轮接入，确保存活线程的来源不被提前删除、计数结果明确、最终清理可确认，旧任务延迟收尾不覆盖新任务状态。

### 由执行器声明实际工作区能力

`runtime` 在 Claude 与 Codex 中不代表相同的工具权限；后续集中表达程序执行、工作区读写、模拟器挂载与执行位置，供准备、聊天、唤醒、游玩、工具登记和提示词共同使用。验收保留 host Codex 的容器程序通道，拒绝 host Claude 不支持的组合，并确认没有退回宿主机执行。

### 统一录音状态镜像与重建契约

两条录音路线及独立 FMOD 混音经过多次演进，后续明确各自的时钟、样本单位、事件镜像与初始化顺序，区分对象本地状态、祖先继承的有效状态和录制系统施加的暂停；初始快照与后续事件同步使用一致规则。暂停继承和块边界的具体缺陷已修，不作为未修问题重复列入。

验收覆盖冻结时重建、双音轨、一次性音效、音量／参数变化、暂停恢复及音频块接缝；一条路线或局部舍入公式通过不能代替另一条路线的完整验收。

### 让集成测试保留真实的内部调用链

已有部分测试把菜单宏整体 mock 成成功，或把执行器能力预设直接写成断言，未能检出真实组合错误。后续提供可复用的外部菜单／进程／音频边界模拟，保留真实主控入口、状态变更和适配器分发，按执行器、模式与生命周期组合验证公共契约；历史触发链纳入场景回归，断言用户可见结果及资源最终状态。复用现有共享音频校验，覆盖双声道、阈值和跨块边界，避免各诊断脚本另写一套判定。测试数量、统计完整或接口成功均不能单独作为流程验收结果。
