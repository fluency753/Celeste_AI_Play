# 主控模拟能力

预置模拟器是可选的主控能力，工作区和 agent 容器没有模拟器二进制或 SDK。只有用户开启限额使用、配置了可用模拟器、试玩正在运行且额度足够时，主控才接受预测；准备、暂停、聊天和结束后均不能预测。

- 调用 `{tool:simulate}`，例如 `{"candidates":[["30,R","1,R,J","29,R,J"]],"request_id":"room-a-batch-1"}`。每个有效批量请求占一轮，最多 256 条候选，每条最多 6000 帧，合计最多 60000 帧；从当前真实帧预测，不推进游戏。
- 具备工作区文件和程序通道时，可以生成、筛选候选。候选多时写成 JSON 文件，例如 `{"candidates":[["60,R"]],"input_format":"celeste_ai"}`，调用时传 `request_file`，不要同时传 `candidates`。文件只承载结构化输入，不是主控执行的脚本；没有文件工具通道时直接传 `candidates`。
- 具备工作区文件通道时，可以按需读取完整结果与轨迹，保存在工具返回的 `/workspace/game/simulation/<receipt>.json`；这是数据，不含模拟器实现。结合候选和预测轨迹生成计划文件，再用 `{tool:act}` 执行。
- 实际预测必须显式提供 `request_id`；省略时未执行、未扣费。相同 `request_id` 和相同请求重试时返回已有回执，不重复执行或扣费；同一 ID 不能换成不同请求。超时或执行结果未确认时，先查询原回执，不用新 ID 重跑。
- 不自行寻找、复制或调用模拟器文件；不从历史快照或检查点绕过当前帧与额度限制。预测包含未模拟机制或警告时，结合真实反馈判断。
