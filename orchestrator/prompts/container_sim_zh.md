# 工作区与自写程序

你运行在一个断网的 Linux 容器里，除了游戏工具，还可以用 Bash、Read、Write、Edit、Glob、Grep。

- `/workspace`：你的工作区，可写。里面的文件跨房间、跨章节、跨运行保留，之前写的程序和笔记都还在，先看看有什么。
- `/kb`：只读知识库，记录游戏的物理常量与机制规则（只讲规则，不讲关卡怎么过）。**开始游玩前要把它从头到尾完整读一遍**（第一条消息会列出文件和顺序，主控按行核对，读完之前游戏工具不执行）。上面的物理参数只是简表，精确的帧数、更新顺序与边界条件以知识库为准；各种高级技巧的触发条件、输入写法与帧窗口见 `/kb/techniques.md`。`/kb/reference/` 收录了社区资料原文（Celeste Wiki 的全部技巧页面、草莓酱训练场与机制库的全部说明、反向钟《Celeste 机制详解》等），可以用 Grep 查技巧名；文字版看不到的插图，可以用 Read 打开 `/kb/reference/community/pdf/` 里的原 PDF。
- 预装 Python 3（numpy、scipy、numba、pillow、networkx）与 gcc / g++。容器没有网络，不能安装新的软件包，也不能访问任何网站。
- 每次 `observe` / `act` 之后，主控会把数据写进工作区：完整观测在 `/workspace/game/latest_obs.json`，上一次 `act` 的逐帧轨迹在 `/workspace/game/last_act.json`，每个房间第一次的观测另存一份在 `/workspace/game/rooms/` 下。文件格式见 `/kb/game_data.md`。
- `act` 可以直接执行计划文件：把按键段写成 JSON 文件（例如 `["12,R", "1,R,J", "15,R,J"]`），调用 `act` 时传 `plan_file`（工作区里的路径）而不传 `inputs`，省去把按键抄进参数。计划文件还可以写成对象（格式见 `/kb/game_data.md` §3）：
  - `expect`：模拟器预测的逐帧位置（可附状态名）与 `tolerance` 容差。实际与预测相差超过容差，就在那一帧停下（`deviate`），并告诉你从第几帧开始不一致。
  - `retry`（只在不限制规划轮次的运行里生效）：重算命令。死亡、偏离预期（或按键用完仍在本房间）时，主控在零网络沙箱里运行它，它从当前状态重算并改写同一个计划文件，主控接着执行，最多 `max` 次，期间不唤醒你。

建议：**直接用预置模拟器**（见下文"预置模拟器"），不要自己再写一个模拟器。你的程序主要写搜索与规划：在观测给出的房间几何上以"到达出口所需帧数最少"为目标自动规划按键序列（把各种高级技巧作为宏动作纳入搜索），生成计划文件后交给 `act` 执行。**针对具体的房间结构设计搜索**：根据地形、尖刺、平台、实体与出口的位置，为这个房间定制剪枝条件（例如提前剪掉注定掉坑、撞上尖刺、离出口越来越远或明显比已知路线慢的分支）与引导条件（例如中间目标点、先上某个平台再去出口、按离出口的距离或预计剩余帧数排序），用什么算法（A*、广度优先、束搜索、随机或进化搜索……）也由你决定，还可以根据上一次搜索的结果调整方向。把模拟器预测的轨迹写进计划的 `expect`，实际偏离时会在那一帧停下。写好的搜索程序要在后面的房间和章节反复使用，按房间改剪枝与引导条件。Bash 单条命令有运行时间上限，长的搜索要自己设时限。
