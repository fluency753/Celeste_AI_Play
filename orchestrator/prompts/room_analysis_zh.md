# 从房间数据建立路线

主控提供原始数据，空间通路和动作可行性由你判断。

- **先核对数据，再选动作。** {observation_source_rule}。核对帧号、章节、房间与覆盖范围；未知形状、缺字段或局部未见都不等于空地。按实际返回格式读取：原始 `objects[].geometry` 已是世界坐标；回退 `room-context-v2` 按 `instanceColumns`、组属性与形状表还原，delta 核对 `base_snapshot_id` 并应用增删改，不能因没有 `objects` 就认为缺数据。需要刷新或快照链缺失时默认 observe；已有同帧数据不重复查询，区域疑点才用 `observe(detail="geometry", region=[x,y,w,h])` 精查。
- **先找身体能经过的通路。** 用角色碰撞箱、支撑面、墙体、实际开口与通道宽高，明确从哪个开口、哪侧绕过，再选落脚点或隔墙目标。截图与碰撞图帮助定位，不能凭贴图或包围盒断定实心、安全或可达；圆形、组合、稀疏 Grid 使用真实形状。`exits` 只是房间边界投影，必须找到真实入口。不能用中心连线或直线距离变小代替通路依据；已知堵墙不重复平推或盲搜。
- **再验证动作可行性。** 结合高差、速度、冲刺、体力、危险物及实体机制设计动作；区分静态地形、单向平台、可破坏物、梦境块和移动实体。`kind` 不是永久通行规则，结合 `category`、`collidable`、姿态和当前状态判断；站立过不去不代表下蹲或其他时机也过不去。`mutable=true` 的对象以后可能变化，当前零速不代表静态；`collidable=false` 仍有形状。尺寸或机制不明时查资料或针对性验证，不把假设当事实；`game/rooms/` 历史快照不能替代当前状态。
- {geometry_program_rule}有依据的候选足够后就做动作或模拟验证，不必穷举；找不到入口的区域记作待查，可能需要从别房进入，不断言永久不可达。候选优先级遵循本次目标：探索选择近期尝试；速通仍须在执行前推演整房路线。
- **按反馈修正并复用。** {geometry_record_rule}换房、状态变化或预测偏离时只更新受影响部分，未变化的数据、连接与结论继续使用；同一假设被否定后换入口、机制或验证问题，不持续扩大搜索。
