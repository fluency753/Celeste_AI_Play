# 从房间数据建立路线

房间路线由你根据原始几何和游戏机制判断，主控提供数据，不预先给出可达性结论。

- **按返回格式读取已有布局，不按截图猜尺寸。** {observation_source_rule}。默认返回 `workspace-files-v1` 时，按文件路径从原始 `obs` 读取所需区域，不额外调用全局／局部工具获取同帧已有数据；回退到 `room-context-v2` 时，其 baseline 在 `collision.groups/instances` 中，按 `instanceColumns` 读取实例，结合组上共同字段与 `shapes` 还原；后续 delta 核对 `base_snapshot_id`，应用增删改，不因没有 `objects` 就认为缺数据。区域精查 `shared-shapes-v1` 才返回 `objects` 的 `shape/at`；原始工作区 `obs.collision.objects[].geometry` 则直接使用世界坐标，不能再次加锚点。先核对帧号、章节、房间及来源覆盖，未知形状或局部未覆盖不能当空地。
- **先用几何核对下一段通道。** 选择新落脚点、隔墙目标或穿越区域前，用当前角色碰撞箱核对支撑面、墙体、实际开口、通道宽高及障碍的类别和碰撞状态；将“从哪个开口、哪侧绕过”落实后再选动作。截图和碰撞图用来定位候选、帮助理解，不能凭贴图认定实心墙、单向平台、假墙或安全空隙。已有布局和变化足够时直接行动，不要求每步额外查询或运行程序；需要快捷查看或没有脚本能力时，才用 `observe(detail="geometry", region=[x,y,w,h])` 精查。文件模式下，动作后读最新文件；需要刷新数据时默认 observe，不为重复获取同帧几何额外查询。回退布局的快照链缺失或历史压缩后忘记布局时，默认 observe 重建。
- **动态状态只对快照帧成立。** 实体 `mutable=true` 表示后续可能移动、变形、失去碰撞或消失，当前零速或未观察到移动不代表静态；`collidable=false` 仍保留形状但当前不参与碰撞。`kind` 是碰撞类别而非永不可穿越，梦境块、门等还要结合 `category` 和状态。圆形、组合和稀疏 Grid 按当前格式使用真实形状，未知形状不能用包围盒当实心。碰撞图的分色帮助快速发现阻挡，不提供未来可达性结论；`game/rooms/` 是历史快照，不能作为当前实体位置。
- **先构建空间关系，再选搜索目标。** 从地形矩形的边缘、实际开口和通道宽高，判断角色身体能经过哪些空间，找出能站立的顶面、可抓墙面及它们之间的连接。{geometry_program_rule}不要只连角色中心与目标点，也不要把到目标的直线距离变小当作通路成立；已有精确几何能排除的直行，不反复用撞墙或盲搜再确认。
- **把空间通路与动作可行性分开验证。** 在候选通路上结合支撑、所需高差、速度、冲刺、体力和危险物设计动作。区分静态地形、单向平台、可破坏物、梦境块和移动实体，查看 `collidable`、`shape` 与状态；站立身体过不去不代表下蹲、特殊机制或其他时机一定过不去。机制不明时保留假设，用针对性的模拟或真实结果验证。
- 碰撞状态、形状或姿态尺寸缺失时，查接口资料或做针对性验证；缺字段不是“不碰撞”，假定的身体尺寸也不是已验证事实。
- **出口和目标都需要实际入口。** `exits` 只是相邻房间边界的投影，先找真实开口及通向它的空间。对隔墙的物体、另一片区域或边界目标，明确准备通过哪个开口、姿态或机制到达；找不到依据时换候选目标或核验疑点，不在相同假设上持续增加搜索。可能需从其他房间进入的区域记作待查，而非认定当前必达或永久不可达。
- **按结果修正自己的空间模型。** {geometry_record_rule}换房、碰撞状态变化或预测偏离时更新相关部分，未变化的数据和结论继续复用。探索模式用这些信息选择近期尝试；速通模式据此规划并优化整房路线，保持各自的执行规则。
- 候选优先级遵循本次目标与模式。空间分析足以筛选有依据的候选后就转入动作验证，其余区域记作待查，不必穷举；这不免除速通模式执行前对整房路线的推演要求。
